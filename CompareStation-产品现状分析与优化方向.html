CompareStation 产品现状分析与优化方向

分析基线：main @ 09393686 + 2026-09-22 未提交工作区（PairMetrics、图片高位深 sidecar、Alpha 互斥、图片 Fade 等）· 分析方式：全链路代码阅读 + 同类开源软件调研 · 本页所有打分均为代码阅读估计，非实测数据

0. 一句话结论

这个项目的工程底子比绝大多数个人开源项目都要好——分层清晰、防御性强、测试与门禁完整、文档同步维护。真正的短板不在"能不能用"，而在四点：

  • 兼容面窄：视频只认 H.264/HEVC/MPEG-4 Part 2，与"兼容大多数压缩格式"的目标有距离（AV1/VP9 是第一步）。
  • 对比感知还不够强：放大镜（loupe）、双误差图、候选快速切换、"哪个候选更接近 GT"这类"看出差异"的手段还缺。
  • 三图工作流是下一步主战场：视频侧已有三源模型，图片侧此前拍板"不做 3 图"，本次需求重新开启，需要一次设计定稿。
  • 上手体验靠"入口"而非"引导"：首屏入口已补上，但模式很多（视频 8 种视图 × 7 种指标 + 图片 7 种对比模式），还差一层"按任务组织"的引导。

另有 5 个 P0 级别的"统计/对齐语义"风险点（不是崩溃，而是可能误导比较结论），详见第 2 节。

1. 四工作流能力现状

评分依据：格式兼容（编解码/格式矩阵）、性能流畅（解码与渲染管线/大图延迟，含待验证项）、功能完整（定位/逐帧/对比模式/Alpha 等能力覆盖）、像素保真（原始码值 vs 显示转换的诚实度、ICC）、交互体验（OSC/时间轴/快捷键/引导）、测试覆盖（分层测试与门禁）。

视频播放

  • 解码：FFmpeg + D3D11VA（单共享设备），软解回退带原因可查；NV12/P010 直通渲染。
  • 定位：精确 seek（含 Open-GOP 回退）、反向 GOP 窗口、逐帧/5帧/1秒、区间循环、倍速阶梯。
  • 状态：OSC 状态轨区分"源重复帧 / 播放器跳帧 / 呈现间隙"三类现象。
  • 短板：编解码只有 3 种；4K 不在性能门禁内；V-01/V-02 统计语义待硬件验证。

视频对比

  • 视图：SideBySide / ThreeUp / ReferenceFocus / Difference / AnalysisGrid / Wipe / Fade / Single。
  • 指标：RGB/Luma/Chroma/Heatmap/SignedSubtract/Highlight 等 + 增益 1–16× + 阈值 + ROI。
  • 三源：A/B/C 槽位、参考聚焦、对齐偏移（全局/自动/手动锚点）、缺帧/重复帧诊断。
  • 短板：无放大镜 loupe；无"双误差图并列"；V-03 帧序号 vs 时间对应语义待完善。

图片查看

  • 格式：PNG/JPEG/BMP/GIF/WebP/TIFF/PNM(P1–P7) 经 FFmpeg 解码 + 头探测 + 文件夹配对。
  • Alpha：A/O/B 快捷键、棋盘格/黑白底、Alpha 灰度、忽略透明度 RGB、观察状态徽标。
  • 高位深：>8bit 源同步生成 RGBA64 sidecar，取样区分"原始码值"与"显示值"。
  • 短板：无 ICC 色彩管理；大图通道首帧延迟未实测（I-06）；动画 GIF/WebP/TIFF 多页不支持。

图片对比

  • 模式：SideBySide / AbsDifference / SignedDifference / Highlight / Wipe / AlphaDifference / Fade。
  • 交互：原地 A/B（Space 按住）、自动 Flicker 闪烁、并排同步十字准星、Fade 滑杆。
  • 统计：MAE/峰值差/Alpha 统计 + "放大×4 统计为原始值"口径标注。
  • 短板：三图对比此前关闭、本次重启待设计；"平均差异"与视频 MAE 定义分叉（I-05）；无对比结果导出。

5. 建议路线图

  • 批次 1 · 可信观察（P0 正确性，约 1–2 周） V-01 状态语义硬件验收 · V-02 追赶体验验证 · V-03 帧序号/时间规则定稿 · V-05/I-02 显示保真验收 · I-05 统计口径标注。结束后"看到的数字不会误导结论"。
  • 批次 2 · 核心工作流（P1，约 2–4 周） AV1/VP9 支持（1080p 内验收）· 视频放大镜 loupe · 三图对比落地（方案 B 默认 + A 精看）· I-06 大图性能。结束后四条工作流在真实素材上可完整走通。
  • 批次 3 · 插帧审查与导出（约 1–2 周） 生成帧条带（需先定生成帧规则）· 对比结果导出 PNG/GIF · 快捷键/引导完善（按任务组织模式）。
  • 批次 4 · 专业增强（P2，持续） ICC 色彩管理 · 直方图/波形 · 批注涂鸦 · 指标外部导入 · 双误差图进阶（方案 C）。

映射关系：批次 1 ≈ 台账"批次 1"；批次 2 ≈ 台账"批次 2+3"；批次 3/4 ≈ 台账"批次 4"及新增项。工程健康项（提交、拆文件、清理）随批次推进，不单独占批次。

6. 需要您拍板的问题

  1. 已拍板三图对比确认重启：默认方案 B（三联 + 双误差图），方案 A（固定 GT + 切换候选）保留为精看模式。实施时按此定稿。
  2. 已拍板格式矩阵范围：按互联网/测试视频、1080p 内验收；先做 AV1/VP9，HDR/4K/ProRes/DNxHR 暂不做。
  3. "跳帧"语义：播放时希望"保真不漏帧（负载高会变慢）"还是"实时优先（可以跳帧追赶）"？当前默认是实时优先（RealTime）；逐帧审查模式才不漏帧。是否需要把默认改成不漏帧？
  4. 生成帧规则：插帧审查要"只看生成帧"，生成帧如何识别？文件命名/元数据/用户指定，三选一或组合？没有规则就无法自动标记。
  5. GT 与 Prediction 是否同帧率、同尺寸：决定 V-03 对齐语义与比较可用性；请确认最常见的工作素材形态。
  6. "PPNM"格式样例：目前按 PNM 家族（PBM/PGM/PPM/PAM，P1–P7）处理，覆盖 8/16 位和 RGBA（PAM）。如有真实样例请提供 1–2 个，确认没有特殊变体。

7. 结束语

结论：架构与工程质量是资产，不是负债。当前阶段最值得投入的顺序是：① 把 P0 语义验证做完（让结论可信）→ ② 扩兼容（AV1/VP9）→ ③ 三图工作流与放大对比（让结论看得清）→ ④ 上手引导与导出（让结论带得走）。

不建议做的事：不扩展音频/字幕、不引入项目文件格式、不做自动主观质量裁判、不为单一功能重写播放内核。以上都超出当前产品目标且收益低。
