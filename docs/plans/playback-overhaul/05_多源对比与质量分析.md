# 05｜多源对比与质量分析方案

## 核心结论

Toy 当前已经具备高质量的 1～3 路同步呈现和视觉差异渲染，但其产品语义仍以 A/B/C 槽位为中心。要支持“GT 与任意候选比较”“多个 Candidate 排名”“每个视频的统计分析”，必须先把**源身份、业务角色、时间线主源、活动 Pair 和渲染槽位**分开，再构建可溯源的分析引擎。

推荐的核心模型是：

```text
Loaded Sources（可多于 3）
    ├── Timeline Master：只定义 canonical timeline
    ├── Reference：业务上的 GT/基准
    ├── Active Pair：当前 Wipe/Diff/Metric 的两路
    ├── Focused Source：单路查看/像素检查目标
    └── Active Presentation Set：当前真正解码/呈现的有限源集合
```

这样，Reference 可以固定为 GT，用户可以从候选列表中选择 C1/C2/C3 与 GT 对比，而不会因为候选数量和载入顺序改变 A/B/C 的含义。

## 一、Comparison Semantics V2

### 1.1 稳定身份

```cpp
struct SourceKey final {
    Uuid value;
};

struct SourceRecord final {
    SourceKey key;
    SourceFingerprint fingerprint;
    QString displayName;
    std::optional<QString> userAlias;
    SourceRole role = SourceRole::Candidate;
    MediaDescriptor descriptor;
};

enum class SourceRole {
    Reference,   // GT / Baseline
    Candidate,
    Auxiliary,   // mask、debug render、motion vector visualization 等
};
```

`SourceId`/slot 可以继续作为一次运行中的高效索引，但所有会跨拓扑、重排、保存、异步分析的状态都必须使用 `SourceKey`。

### 1.2 四个独立选择

```cpp
struct ComparisonSelection final {
    SourceKey timelineMaster;
    std::optional<SourceKey> reference;
    std::optional<SourcePair> activePair;
    std::optional<SourceKey> focusedSource;
};

struct SourcePair final {
    SourceKey first;
    SourceKey second;

    [[nodiscard]] SourcePair canonicalized() const;
};
```

这些字段不能互相隐式派生。允许：

- Timeline Master = GT，Reference = GT，Pair = GT/Candidate 2；
- Timeline Master = Candidate 1，Reference = GT，Pair = GT/Candidate 3；
- 没有 GT，Pair = Candidate 1/Candidate 2；
- 单源播放，没有 Pair；
- 参考源暂时不可用，但 Timeline Master 仍有效。

### 1.3 Pair 的有序与无序语义

多数绝对差指标是对称的，但 Wipe 左右、Signed Difference、Blend 前后景、Reference-minus-Candidate 是有方向的。因此建议同时定义：

```cpp
struct UnorderedPairKey { SourceKey low; SourceKey high; };
struct DirectedPairKey { SourceKey primary; SourceKey secondary; };
```

- 对称缓存（MSE/PSNR/abs diff）用 `UnorderedPairKey`；
- Wipe/Blend/Signed Diff 用 `DirectedPairKey`；
- UI 允许“交换左右”，但交换不应改变 Reference 或 Timeline Master。

### 1.4 拓扑变化规则

当源被删除或重排：

- `SourceKey` 不变；
- RenderSlot 可以重新分配；
- 若 Active Pair 某端被移除，按明确策略回退：
  1. Reference 仍存在：Reference + 最近使用候选；
  2. 否则选择两个可用源；
  3. 不足两源则 Pair 清空；
- 不得恢复全局 Preferences 中陈旧的 0-2/1-2 序号；
- 用户默认偏好只保存“Reference vs first candidate”等策略，不保存本会话 Pair 身份；
- 每次自动回退都发出可解释事件，不能静默改变比较对象。

## 二、N 源逻辑模型与有限活动集

### 2.1 不直接把完整 FrameSet 扩成 N 路

当前 3 路上限贯穿固定数组、枚举、renderer、QML 和测试。直接改成 8/16 路会同时放大：

- 解码线程数量；
- GPU 纹理驻留；
- FrameSet ACK fan-in；
- UI 复杂度；
- 差异 Pair 枚举；
- 内存预算；
- 任何一路慢源对全部源的阻塞。

推荐把“已加载源数量”和“同时呈现源数量”分离：

```cpp
struct PresentationSelection final {
    std::vector<SourceKey> visibleSources; // 通常 1～3，特殊 grid 可 4
    std::optional<DirectedPairKey> pair;
};
```

会话可加载 N 个候选，但实时解码/显示只针对活动集合。后台统计可以单独调度，不进入实时 FrameSet。

### 2.2 活动集合切换

切换候选时执行安全事务：

1. 记录当前 canonical `MediaTime`；
2. 生成新的 `TopologyRevision`/`PresentationSelectionRevision`；
3. 为新活动集合准备 provider；
4. 映射到同一 canonical 时刻；
5. 获取完整新 FrameSet；
6. ACK 后原子切换；
7. 旧资源按 generation/device fence 退休；
8. 失败时保留旧活动集合。

UI 可以显示候选切换进度，但旧画面不应先黑掉。

### 2.3 候选浏览模式

建议新增候选导航：

```text
Reference: GT
Candidate: C03  [上一候选] [下一候选]
Pair: GT ↔ C03
```

快捷键可以是 `[` / `]` 或可配置命令，切换后保持：

- canonical media time；
- zoom/pan/ROI；
- difference metric；
- threshold/gain；
- In/Out range；
- 分析上下文。

## 三、视觉比较模式升级

### 3.1 保留并规范现有模式

现有模式继续支持：

- Single；
- Side by Side；
- Three Up；
- Reference Focus；
- Wipe；
- Difference；
- Analysis Grid。

每个模式通过 descriptor 声明：

```cpp
struct ComparisonModeDescriptor final {
    ComparisonModeId id;
    SourceCountRange visibleSourceCount;
    bool requiresPair;
    bool supportsRoi;
    bool supportsThreshold;
    bool supportsPixelInspector;
    bool supportsPlayback;
    ComparisonDomain defaultDomain;
};
```

QML 和菜单只能消费 descriptor，不再手写两套 available-mode 数组。

### 3.2 Blink

Blink 对细微几何漂移和纹理闪烁非常有效。

```cpp
struct BlinkSettings {
    std::chrono::milliseconds period{250};
    float dutyCycle = 0.5F;
    bool freezeOnPointerDown = true;
};
```

要求：

- 两路使用同一完整 FrameSet；
- Blink 只在 renderer 中切换可见源，不触发解码；
- 支持 2/4/8 Hz 等预设；
- 暂停、播放均可用；
- UI 明确显示当前可见端；
- 读屏用户有非视觉状态提示；
- 导出证据时记录频率和 Pair。

### 3.3 Blend / Opacity

```cpp
struct BlendSettings {
    float primaryOpacity = 0.5F;
    BlendMode mode = BlendMode::Linear;
};
```

优先实现线性插值，后续可选 Difference Blend。Opacity 滑杆必须支持键盘与可访问值。Blend 使用有方向 Pair，交换左右会改变视觉结果。

### 3.4 Wipe 方向

扩展为：

- Vertical；
- Horizontal；
- Diagonal（后续）；
- Split position 可数值输入；
- Reset 50%；
- 键盘微调 1%，Shift 5%；
- 双击恢复中点；
- 可选 feather edge，但默认关闭以避免误判精确边界。

### 3.5 Pixel Inspector

专业比较需要能回答“这个像素具体差多少”。

```cpp
struct PixelSample final {
    SourceKey source;
    FrameId sourceFrame;
    PixelCoordinate sourceCoordinate;
    PixelCoordinate displayedCoordinate;
    PixelCodeValue nativeCode;
    LinearRgbValue displayLinear;
    bool resampled;
};

struct PixelComparisonSample final {
    PixelSample first;
    PixelSample second;
    DifferenceVector difference;
    ComparisonDomain domain;
    ComparisonExactness exactness;
};
```

UI 显示：

```text
GT      x=812 y=443  Y=64 U=122 V=131
C03     x=812 y=443  Y=69 U=120 V=134
Δ       Y=+5 U=-2 V=+3
Domain  Exact plane codes
Frame   canonical 1024 · GT 1024 · C03 1022
```

如果存在旋转、SAR、ROI、缩放或时序映射，必须同时报告 source coordinate 和 display coordinate。不能把插值后的值标成原生像素。

## 四、比较域与精确性溯源

### 4.1 统一 ComparisonDomain

```cpp
enum class ComparisonDomain {
    ExactPlaneCode,       // 原始归一化 Y/UV code values
    DisplayEncodedRgb,    // 经过矩阵/range/transfer 到显示编码 RGB
    DisplayLinearRgb,     // 线性光 RGB
    LumaOnly,
    ChromaOnly,
    Perceptual,
};
```

每个 metric、差异纹理、导出结果都必须带 domain。

### 4.2 统一 Provenance

```cpp
struct ComparisonProvenance final {
    SourceFingerprint first;
    SourceFingerprint second;
    TimelineRevision timeline;
    AlignmentRevision alignment;
    FrameMappingRevision mapping;
    ComparisonDomain domain;
    DifferenceMetricId metric;
    SpatialTransformVersion spatialTransform;
    ColorPipelineVersion colorPipeline;
    std::optional<Roi> roi;
    std::optional<FrameRange> range;
    bool spatiallyResampled;
    bool temporallyMapped;
};
```

导出 JSON/CSV/截图时嵌入这份 provenance。用户随后才可以判断两次结果是否真的可比。

### 4.3 精确性分级

保留现有分类思想，并扩展成结构化原因：

```cpp
enum class ComparisonExactness {
    ExactCodeValue,
    DisplaySpaceConverted,
    SpatiallyResampled,
    TemporallyAligned,
    Unavailable,
};

enum class ExactnessReason {
    DimensionMismatch,
    RotationMismatch,
    SarMismatch,
    PixelFormatMismatch,
    BitDepthMismatch,
    ColorMetadataMismatch,
    NonExactFrameMapping,
    MissingFrame,
};
```

UI 不只显示“Spatially resampled”，还应允许查看原因。Metric API 可以声明最低精确性要求，例如 Exact Plane Mismatch 必须是 `ExactCodeValue`。

## 五、量化指标引擎

### 5.1 分层实现

不要让实时 renderer 兼任整段统计引擎。建议三层：

1. **Interactive GPU Metric**：当前帧、低延迟、支持 ROI；
2. **Frame Metric Worker**：后台计算选定帧或小范围；
3. **Sequence Analysis Job**：整段/范围批量统计、进度、取消、持久结果。

统一端口：

```cpp
struct MetricRequest final {
    AnalysisRequestIdentity identity;
    DirectedPairKey pair;
    MetricSet metrics;
    FrameSelection selection;
    std::optional<Roi> roi;
    ComparisonDomain domain;
};

class IComparisonMetricService {
public:
    virtual PortSubmitResult submit(
        MetricRequest,
        std::shared_ptr<IMetricEventSink>) = 0;
    virtual void cancel(AnalysisRequestIdentity) noexcept = 0;
};
```

### 5.2 首批指标

优先实现可解释、容易验证的指标：

| 指标 | 作用 | 注意事项 |
|---|---|---|
| MAE / Mean Absolute Error | 平均误差直观 | 必须声明通道与 domain |
| MSE | 后续 PSNR 基础 | 对离群值敏感 |
| PSNR | 常见重建质量 | 相同 bit depth/range 定义 MAX |
| Pixel mismatch ratio | 精确/阈值不一致比例 | 可与 threshold 联动 |
| Max absolute error | 定位极端错误 | 同时返回坐标 |
| Mean luma/chroma error | 区分亮度与色度 | 色度采样网格需说明 |
| SSIM（第二批） | 结构相似度 | 需固定窗口、边界与色域 |
| Temporal flicker proxy（第二批） | 检测帧间差异不稳定 | 不能与单帧质量混为一谈 |

VMAF 可以作为可选外部 worker，不应进入第一批，因为模型版本、输入预处理和许可证/部署会增加溯源成本。

### 5.3 每帧结果

```cpp
struct FrameMetricResult final {
    FrameId canonicalFrame;
    std::optional<FrameId> firstSourceFrame;
    std::optional<FrameId> secondSourceFrame;
    FrameMatchKind firstMatch;
    FrameMatchKind secondMatch;
    ComparisonExactness exactness;
    std::vector<MetricValue> values;
    std::optional<PixelCoordinate> worstPixel;
};
```

缺帧不是 0 分，也不是无限误差；它应作为独立状态进入统计：

```cpp
enum class FrameMetricAvailability {
    Available,
    FirstMissing,
    SecondMissing,
    BothMissing,
    IncompatibleDomain,
    DecodeFailed,
};
```

### 5.4 序列聚合

每个 Pair/指标至少产出：

- count / available / missing；
- mean；
- median；
- p5/p25/p75/p95/p99；
- min/max；
- worst K frames；
- threshold exceed count/ratio；
- 连续异常区间；
- 按时间段/场景分桶；
- ROI 与全帧独立统计；
- exactness 分类占比。

禁止只输出一个平均值。视频中的短暂严重问题很容易被平均稀释。

### 5.5 多候选矩阵

当有一个 Reference 和多个 Candidate：

```text
                C01      C02      C03
PSNR mean       36.2     34.8     37.0
PSNR p5         28.1     30.4     27.5
SSIM mean       .962     .954     .965
Missing frames  0        3        0
Worst segment   12.4s    31.8s    08.1s
```

排序必须由用户选择规则：

- mean best；
- worst-frame best；
- p5 best；
- threshold failures least；
- composite score。

不要自动合成一个未经解释的“总分”。Composite score 必须展示公式、权重和版本。

## 六、每个视频自身的统计分析

用户不只需要 Pair 指标，也需要每个 Source 的独立质量/媒体统计。建议新增 `SourceAnalysisReport`：

### 6.1 媒体与解码统计

- codec/profile/level；
- container；
- resolution/SAR/rotation；
- bit depth/pixel format；
- color matrix/range/transfer/primaries；
- CFR/VFR 与时间线置信度；
- duration/frame count 来源；
- keyframe/GOP 分布；
- decode backend、fallback reason；
- 平均/最大 decode latency；
- cache hit；
- corruption/decode warning；
- changed-on-disk identity。

### 6.2 时序完整性

- duplicate PTS；
- non-monotonic DTS/PTS；
- frame duration 分布；
- missing/extra/duplicate mapping；
- 与 canonical timeline 的 offset/confidence；
- longest missing run；
- longest repeated run；
- VFR interval histogram。

### 6.3 画面统计

第一阶段可计算：

- luma mean/std/histogram；
- clipped black/white ratio；
- chroma mean/variance；
- per-frame entropy/edge-energy proxy；
- freeze/near-duplicate frame ratio；
- scene-cut candidates；
- black-frame/solid-frame detection。

这些是诊断统计，不应被包装成“主观画质评分”。

### 6.4 结果呈现

Inspector 分为：

```text
Source
  Identity / Media / Decode / Timing / Signal

Comparison
  Active Pair / Exactness / Current Frame Metrics / ROI

Sequence
  Summary / Worst Frames / Segments / Candidate Matrix
```

用户点击 worst frame/segment 应直接跳转并保留当前 Pair、ROI 与比较模式。

## 七、分析调度与资源隔离

### 7.1 优先级

```cpp
enum class WorkPriority {
    InteractiveNavigation,
    InteractiveComparison,
    PlaybackPrefetch,
    UserRequestedAnalysis,
    BackgroundThumbnail,
    BackgroundIndexing,
};
```

整段统计不得抢占播放。建议：

- 播放时暂停或降并发；
- 用户显式“分析范围”可继续，但 UI 显示性能影响；
- Worker 数量和 GPU queue 有上限；
- 与主 FrameBudget 分区或使用可回收低优先级配额；
- cancellation token 必须下传到 decode/metric/reduction；
- 进度基于可解释工作单元，不伪造平滑百分比。

### 7.2 增量与缓存

结果缓存键包含完整 provenance。支持：

- 当前帧即时结果；
- 范围增量扩展；
- 已完成块复用；
- 文件 fingerprint 改变自动失效；
- metric implementation version 改变自动失效；
- crash 后可恢复已原子提交的 chunk；
- 不把部分结果冒充完整结果。

### 7.3 GPU 与 CPU

首批可采用：

- 当前帧 diff/简单 reduction：GPU；
- 整段 MAE/MSE/PSNR：GPU compute 或并行 CPU，基准后决定；
- SSIM：独立可替换 backend；
- 所有 backend 必须通过同一 reference implementation 校验；
- GPU 加速结果允许浮点微差，但门禁必须定义绝对/相对容差；
- Exact code mismatch count 应使用整数路径，不能靠浮点近似。

## 八、可视化设计

### 8.1 当前帧

- Metric chips：PSNR、SSIM、Mismatch；
- Exactness badge；
- 点击展开 domain/provenance；
- Threshold 控件与 mismatch mask 联动；
- Pixel Inspector 跟随鼠标，可锁定位置。

### 8.2 时间序列

- 一次只突出 1～3 条主曲线，避免候选过多时不可读；
- 支持 Reference vs selected Candidate；
- 候选切换不改变纵轴；
- hover 显示 canonical/source frame mapping；
- missing/duplicate 作为离散轨道，不用数值 0 伪装；
- 可框选范围并设置 In/Out；
- worst K 作为 marker；
- 大数据先降采样，但点击时回到原始帧结果。

### 8.3 多候选

- 热力图：Candidate × Metric/Segment；
- 排名表；
- 小倍图只在候选数量较少时使用；
- 每个单元格可跳转至最差片段；
- 清楚区分“统计尚未计算”“不可用”“缺帧”。

### 8.4 导出

首批支持：

- JSON：完整 provenance 与逐帧/聚合结果；
- CSV：扁平化逐帧指标；
- PNG：当前视图/差异/图表；
- Evidence Bundle：manifest + source fingerprints + settings + metrics + screenshots + app build SHA。

导出必须原子写入，失败不能留下看似完成的半文件。

## 九、色彩、HDR 与编码支持的扩展顺序

### 9.1 先修正元数据模型

当前 SDR 模型较窄。扩展 HDR 前，领域层应能表达：

- primaries；
- transfer：BT.709/sRGB/linear/PQ/HLG；
- matrix：BT.601/709/2020 NCL/CL；
- range；
- mastering display metadata；
- content light level；
- chroma location；
- ICC/display profile identity。

### 9.2 比较域规则

- Exact plane：不 tone-map；
- Display-linear：先按源元数据线性化，再进入共同工作色域；
- Display preview：经过显示 tone-map；
- HDR 与 SDR 比较必须明确选择目标域；
- UI 中的“看起来一样”与 code-value exact 必须是两个不同结论；
- 导出 screenshot 记录 tone-map operator 与显示峰值设置。

### 9.3 codec 优先级

在语义/状态/播放 P0 稳定后：

1. AV1；
2. VP9；
3. ProRes/DNxHR（取决于目标用户）；
4. image sequence；
5. HDR profiles；
6. 更广容器/字幕/音频。

每个 codec 都需要真实 fixture、硬件/软件 fallback、B-frame/VFR/rotation/color 元数据门禁，不能只以“能打开”验收。

## 十、阶段性验收

### Comparison Semantics V2

- 加载 GT + C1 + C2，Reference 固定 GT；
- Active Pair 可在 GT/C1、GT/C2、C1/C2 间切换；
- 切换 Pair 不改变 canonical frame/time；
- 删除 C1 后 GT/C2 保持；
- 关闭再开新会话不会恢复旧会话的 0-2 序号；
- 所有 UI 标签使用 alias/filename/role，而不是只显示 A/B/C。

### 指标引擎

- CPU reference 与 GPU 结果在定义容差内一致；
- exact mismatch count 对合成 fixture 完全一致；
- missing frame 不被统计成 0；
- 取消整段分析后无迟到结果提交；
- 文件改变或 alignment revision 改变后旧缓存失效；
- 最差帧点击跳转到正确 canonical/source frame；
- 导出 manifest 可重建同一比较设置。

### N 源模型

- 载入至少 8 个逻辑候选，不同时解码全部；
- 活动 Pair 切换内存受预算；
- 切换失败保留旧 Pair；
- 后台分析不会阻塞主播放；
- source reorder 不改变任何已保存 Pair/结果身份。

最终目标不是让 Toy “显示更多小窗”，而是让它成为**身份稳定、比较域明确、结果可解释、可以从当前帧追溯到整段统计的专业视频质量工作站**。
