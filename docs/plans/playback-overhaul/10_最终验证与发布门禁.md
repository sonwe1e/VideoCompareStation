# 10｜最终验证、CI 与发布门禁

## 核心结论

最终验证必须针对**精确候选发布 SHA**，形成可追溯证据包。单元测试通过、PR CI 通过、开发机手动看起来正常，都不能代替发布门禁。Toy 已经有 Debug/Release、Linux core、Quality、D3D11、pixel capture、性能和打包基础；整改重点是把新的语义、后退逐帧、Range、Scrub、Pair 切换和指标正确性纳入同一证据链。

## 一、候选版本冻结

### 1.1 必须记录

```text
repository
commit SHA
tag
semantic version
dirty state
submodule/dependency lock
CMake version
MSVC/Clang version
Qt version
FFmpeg/vcpkg baseline
Windows build
GPU name
GPU driver
display refresh/DPI/HDR state
runner labels
fixture manifest hash
```

`tested-commit.txt` 必须由 `git rev-parse HEAD` 生成，并与 workflow 输入的 SHA 比较。禁止测试一个 SHA、打包另一个 SHA。

### 1.2 工作区条件

```powershell
git status --porcelain
git diff --check
git rev-parse HEAD
```

- 工作区必须干净；
- 无未跟踪生产文件；
- 版本文件、tag、安装包 metadata 一致；
- 生成代码可由 clean build 重建；
- release notes 与实际范围一致。

## 四、语义门禁

### 4.1 Comparison Semantics Gate

必须覆盖：

```text
GT + C1 + C2
Reference != Timeline Master
Pair GT/C1 → GT/C2 → C1/C2
Swap Pair
remove/reorder/replace
2-source old 0-2 settings migration
failed Pair switch rollback
same media time across switch
stable SourceKey
```

硬指标：

- `timeline_master_unintended_change = 0`；
- `pair_identity_mismatch = 0`；
- `stale_pair_commit = 0`；
- `old_ready_session_lost_on_failure = 0`；
- Wipe/Diff pixel captures 全部匹配。

### 4.2 Persistence Migration Gate

对每个历史 schema fixture：

- load；
- migrate；
- save current schema；
- reload；
- semantic equivalence；
- unknown field preservation policy；
- invalid enum fallback；
- corrupt file recovery；
- atomic write failure。

升级后不得重新写旧 slot-based Pair。

## 五、Playback / Navigation 门禁

### 5.1 Cold / Warm Exact Seek

Fixtures：

- H.264 long GOP；
- HEVC Main10；
- MPEG-4；
- VFR；
- non-zero PTS；
- rotation；
- 1/2/3 source。

指标：

```text
cold_seek_p50/p95/p99
warm_seek_p50/p95/p99
seek_target_mismatch
stale_commit
presentation_timeout
decoder_reopen
```

现有绝对上限可继续作为起点；若目标硬件变化，必须通过基线流程调整，而不是在失败后直接放宽。

### 5.2 Held Forward

- 25～35 Hz deterministic jitter；
- 至少 300 次；
- 单源、两路、三路；
- 冷/热；
- H.264/HEVC；
- software/hardware。

硬指标：

```text
sequence_errors = 0
missing_intermediate = 0
partial_frame_sets = 0
stale_commits = 0
decoder_reopen = 0
command_terminal_errors = 0
```

### 5.3 Held Backward

新增与 forward 等价的门禁：

```text
held_reverse_p50/p95/p99
reverse_window_hit_ratio
reverse_window_build_p95
reverse_exact_fallback
reverse_sequence_errors
reverse_budget_peak
```

硬指标：

- 严格 `N-1`；
- missing intermediate = 0；
- stale commit = 0；
- partial FrameSet = 0；
- command terminal error = 0；
- memory ≤ FrameBudget；
- healthy warmed window decoder reopen = 0。

### 5.4 Playback Policy

**ReviewEveryFrame**

- 0 missing canonical frame；
- 允许 wall-clock 落后；
- UI 状态准确；
- 长 stall 不跳帧；
- 队列仍有界。

**RealTime**

- 不回退；
- 只跳完整 FrameSet；
- drop telemetry 与 trace 一致；
- 恢复后 cadence 稳定；
- UI 报告 drop。

### 5.5 Range

运行：

- 1-frame；
- 2-frame；
- VFR；
- RealTime under stall；
- ReviewEveryFrame；
- 1/2/3 source；
- mapping missing；
- 10,000 loops。

硬指标：

```text
presented_outside_range = 0
out_frame_missing = 0
loop_boundary_partial_set = 0
range_command_terminal_error = 0
stale_boundary_commit = 0
resource_growth_slope ≈ 0
```

## 六、Scrub 与 Thumbnail 门禁

### 6.1 Scrub Workload

- 60 秒；
- Update 输入 120/500/1000 Hz；
- 内核预览上限 15/30 Hz；
- random target；
- Commit/Cancel 交替；
- playback pressure；
- topology change；
- device loss。

指标：

```text
scrub_update_received
scrub_preview_submitted
scrub_preview_dropped_as_stale
scrub_preview_p50/p95
scrub_commit_p95
generation_delta
decoder_reopen
main_playback_regression
```

硬指标：

- authoritative displayedFrame 只在 Commit ACK 后改变；
- Cancel 恢复旧帧；
- generation 不随每个 pointer event 增长；
- late thumbnail 不投影；
- queue/cache 有界；
- GUI thread 无 decode wait。

### 6.2 Thumbnail

- unseen positions；
- source/master/pair revision；
- rotation/SAR；
- LRU；
- low memory；
- corrupt frame；
- independent decoder shutdown；
- window close during callback。

硬指标：

- wrong-source thumbnail = 0；
- stale result = 0；
- cache bytes ≤ limit；
- playback P95 退化不超过预定阈值；
- no leaked handles/threads。

## 八、Fault Injection 门禁

执行矩阵：

```text
provider Busy/Closed
decode fail current/prepared
render publish closed
ACK timeout/late/duplicate
device lost
allocation failure
frame budget reject
thumbnail/analysis exception
disk full
settings/export atomic rename fail
shutdown in every state
```

每个故障验证：

- no crash/deadlock；
- command terminal exactly once；
- `lastError` 分类正确；
- canceled navigation 不显示硬错误；
- last ACKed frame 保留；
- old Ready topology 保留；
- stale event rejected；
- worker/resource retirement；
- UI 有恢复动作。

## 十一、手动关键旅程

自动化之外，候选发布至少人工验证：

### Journey A：单源播放器

Open → Play/Pause → Held forward/backward → Scrub → Fullscreen → Range → Close。

### Journey B：GT 与候选

Open GT/C1/C2 → set Reference → select Pair → Wipe/Blink/Blend/Diff → Pixel Inspector → switch candidate → keep same time/ROI。

### Journey C：分析

Select range → compute metrics → view curve/worst frames → jump → export evidence → reopen result。

### Journey D：恢复

硬件解码 fallback → device loss/recover → changed-on-disk → failed replace rollback → diagnostics export。

### Journey E：可访问性

仅键盘完成 Open、Play、Pair、Wipe、Timeline、Range、Help；读屏检查控件名称和值；200% DPI 检查焦点与布局。

每次手动旅程记录视频、屏幕录制或结构化 checklist，不写“手测正常”四个字结束。

## 十四、发布决策规则

### Release Blocker

- crash/deadlock/UAF；
- partial FrameSet；
- stale commit；
- wrong Pair/source；
- range 越界；
- command terminal 丢失/重复；
- metric 数值/身份错误；
- settings/workspace 数据破坏；
-不可恢复黑屏；
-性能硬门禁失败；
-package/upgrade失败。

### 可延期但必须记录

- 非核心文案；
- 低风险视觉微差；
- 有明确 workaround 的次要可访问性问题（但核心键盘/读屏不能延期）；
- 未进入当前产品边界的 codec/HDR/audio。

### Go 条件

```text
所有 R0/R1 = 0
所有必需 workflow 在 exact SHA 通过
硬件/pixel/perf/soak/package证据齐全
未验证项不影响发布承诺
最终报告和 evidence hash 已签署/记录
```

最终验证的原则是：**发布的不是“代码看起来正确”，而是一组能够证明帧、身份、时序、像素、性能和生命周期都满足契约的可复查证据。**
