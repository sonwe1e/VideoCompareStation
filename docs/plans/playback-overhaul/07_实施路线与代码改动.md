# 07｜实施路线、文件级改动与迁移计划

## 核心结论

整改必须采用**契约优先、测试先行、可回滚的绞杀式迁移**。不建议创建一条长期大分支一次性重写 `PlaybackCoordinator`、`ReviewController` 和 `Main.qml`。每个批次都应：

```text
先记录当前行为与失败用例
→ 新增窄契约/旁路实现
→ 双轨对照
→ 切换一个能力
→ 删除旧路径
→ 通过独立审查与硬件门禁
```

所有阶段都保留单一串行媒体真相、完整 FrameSet、ACK 后提交、旧 Ready Session 回滚能力。下面的阶段顺序是依赖关系，不是工期承诺。

### Trace 事件

最少包含：

```cpp
struct TraceIdentity {
    SessionId session;
    SessionEpoch epoch;
    TopologyRevision topology;
    TimelineRevision timeline;
    AlignmentRevision alignment;
    PlaybackGeneration generation;
    RequestId request;
    std::optional<CommandId> command;
};

enum class TraceEventKind {
    CommandAccepted,
    CommandRejected,
    ProviderSubmitted,
    ProviderCanceled,
    FrameSetReady,
    ProviderTerminal,
    RenderPublished,
    PresentationAcknowledged,
    SnapshotCommitted,
    CommandTerminal,
    DecoderSeek,
    DecoderReopen,
    CacheHit,
    DeviceGenerationChanged,
};
```

Trace 写入环形内存缓冲区，默认不开启磁盘高频日志；诊断导出时序列化。不得让日志 I/O 阻塞 worker。

### 首批失败/基线测试

- `HeldBackwardPresentsEveryIntermediateFrame`：当前预计暴露 exact-seek 路径；
- `ChangingReferenceDoesNotChangeTimelineMaster`：作为 V2 目标红测，旧路径可先标记 expected failure；
- `SessionPairDoesNotLeakAcrossTopology`；
- `RangeLoopNeverPresentsOutsideInclusiveRange`；
- `ScrubLatestWinsWithoutGenerationStorm`；
- `WipeHandleIsKeyboardAdjustable`；
- `TimelineAccessibleValueMatchesPreviewOrCurrentFrame`。

### 退出条件

- 所有现有测试不变绿；
- 新增 trace 不改变时序和性能到门禁外；
- 能从一份 trace 校验 command exactly-once、ACK-before-commit、无 stale commit；
- 目标 GPU runner 保存原始基线，不只保存摘要。

## 阶段 2｜状态所有权与窄 ViewModel

### 目标

兑现现有 façade 预留的能力边界，降低 `ReviewController`、`ReviewShellController`、`Main.qml` 的耦合。此阶段以搬迁为主，不顺带重设计所有 UI。

### 新增 ViewModel

```text
SessionViewModel
PlaybackViewModel
TimelineViewModel
ComparisonViewModel
AlignmentViewModel
NotificationViewModel
ShellViewModel
DiagnosticsViewModel
```

职责：

| ViewModel | 只拥有/投影 |
|---|---|
| Session | sources、roles、topology transaction |
| Playback | playing、requested/displayed frame、actions |
| Timeline | timecode、range、markers、preview |
| Comparison | mode、pair、exactness、ROI、metric settings |
| Alignment | proposal、progress、anchors、mapping |
| Notification | error/toast/operation |
| Shell | chrome/inspector/focus/dialog intent |
| Diagnostics | backend/telemetry/trace export |

### 实施方式

1. `ReviewSessionFacade` 新增真实窄对象；
2. 旧 `ReviewController` 继续存在，内部改为组合这些对象或只做兼容 adapter；
3. 每迁移一组 Q_PROPERTY，增加 parity test；
4. QML 切换到新 façade 属性；
5. 搜索确认旧属性无消费者；
6. 删除旧属性与投影计算；
7. 最后缩小 `ReviewController`。

### 高频/低频投影分离

高频：

- displayed frame；
- progress/timecode；
- frame pending；
- playback state。

低频：

- source media info；
- compatibility findings；
- alignment result；
- error detail；
- source topology。

禁止每次帧变化重建媒体信息、Pair 列表和大 QVariantList。可使用不可变 C++ model/revision 通知。

### Main.qml 瘦身目标

`Main.qml` 最终只包含：

- 顶层布局；
- façade wiring；
-少量窗口状态；
-组件组合。

应移出的逻辑：

- range loop；
- Pair normalization；
- error detail composition；
- alignment status string；
- active source transaction；
- shortcut action定义；
- preview cache生命周期；
- comparison availability计算。

### 架构门禁

新增脚本/测试：

- QML root 最大行数软门禁，逐阶段下降；
- 单个 ViewModel Q_PROPERTY 数量报告；
- `ReviewController` 不得继续新增 property；
- UI model 不链接 D3D11/FFmpeg；
- QML 不出现 `DifferenceEdge` slot ordinal 业务判断；
- Main.qml 不提交媒体时钟命令链。

### 退出条件

- façade 每个 capability 指向独立对象；
- 高频帧更新不会触发大列表重建；
- QML contract tests 全绿；
- 功能行为与阶段 1 完全一致；
- 删除兼容 adapter 前有覆盖率证据。

## 阶段 3｜Playback/Navigation V2

### 目标

显式播放策略、内核 Range Loop、双向逐帧和统一命令终态。

### 文件拆分

从 `PlaybackCoordinator.cpp` 抽出：

```text

NavigationWorkflow.h/.cpp
RangePlaybackWorkflow.h/.cpp
FramePresentationTransaction.h/.cpp
SessionTopologyWorkflow.h/.cpp
CoordinatorState.h
CoordinatorEventRouter.cpp
```

`PlaybackCoordinator` 保持唯一 worker/event loop 和最终 snapshot commit，不创建第二个协调器线程。

### 3.1 FramePresentationTransaction

统一：

- FrameSetReady；
- provider terminal；
- publish；
- presentation deadline；
- ACK；
- stale identity；
- teardown；
- command ownership。

单元测试独立覆盖所有事件排列，减少各工作流复制状态。

### 3.2 Playback Policy

增加：

```text
PlaybackContinuityPolicy
PlaybackSettings
SetPlaybackPolicyCommand（或 preferences-to-command）
```

先让 Contextual 解析为当前行为，建立 parity；再加入 ReviewEveryFrame/RealTime UI。

### 3.3 Range

新增：

```text
SetPlaybackRangeCommand
ClearPlaybackRangeCommand
SetRangeLoopCommand
PlaybackRangeState
```

迁移顺序：

1. Application 先接受 range，但 QML loop 继续关闭；
2. 对照测试；
3. 切换 `Play Range` 到内核；
4. 删除 `Main.qml.onCurrentFrameChanged` 的 loop seek；
5. 删除 Shell 中 `rangeStartPending` 等媒体状态。

### 3.4 Reverse Step

新增：

```text
ReverseWindowProvider interface
FfmpegReverseWindowProvider
ReverseStepRun
```

可以先只支持单源，再以同一 canonical mapping 扩到多源；但单源实现不能写死绕过 FrameSet。

### 3.5 测试

- model-based coordinator tests；
- forward/reverse held stepping；
- exact seek supersession；
- range all boundary cases；
- VFR range；
- device loss during current/prepared；
- provider success/ACK all permutations；
- budget rejection fallback；
- shutdown with every active state。

### 退出条件

- Range 权威完全在 Application；
- held backward 无缺帧；
- playback policy 可见；
- coordinator 文件职责明显缩小；
- command terminal mismatch = 0；
- hardware perf 与 soak 通过。

由 QML Repeater 切到 C++ bucket model，按 visible range 返回聚合结果。

### 退出条件

## 阶段 6｜N 源工作区与候选管理

### 目标

允许载入多个 Candidate，但保持活动解码集合有界。

### 改动

- SessionTopology 从 1～3 放宽到配置上限；
- PresentationSelection 仍限制 1～3/4；
- source list virtualization；
- candidate search；
- provider pool/lazy open；
- Pair switch transaction；
- background analysis scheduler；
- workspace schema。

### 禁止

- 把 `std::array<...,3>` 全部机械改成 vector 后同时解码 N 路；
- 枚举所有 N² Pair 放进 Combo；
- 每次 source list 变化重建所有 decoder；
- 让后台 metric 共享主 sequential cursor。

### 退出条件

- 至少 8 个逻辑源可稳定管理；
- 活动集内存/线程有界；
- Pair switch 失败可回滚；
- source reorder/rename 不使分析缓存错配。

## PR 切片规则

每个 PR 应满足：

- 一个主语义改变；
- 有失败测试；
- 不同时修改无关 UI 与底层算法；
- 包含迁移/回滚说明；
- 记录 baseline 与新结果；
- 独立 reviewer 能在不阅读后续 PR 的情况下验证；
- 删除旧路径与新增路径尽量不跨超过两个 PR；
- 若必须 feature flag，必须有删除日期条件和 owner，不允许永久双轨。

推荐例子：

```text
PR 1：加入 SourceKey，不改变 UI
PR 2：新增 TimelineMaster/Reference 分离领域状态
PR 3：ComparisonViewModel 双轨投影
PR 4：QML Pair 迁移
PR 5：删除 DifferenceEdge 会话持久化
```

不推荐：

```text
“Refactor player architecture and add analytics/HDR/audio”
```

## 数据迁移策略

### Settings

- schema version 明确；
- 迁移函数纯、确定性、可单测；
- 未知枚举不直接 static_cast；
- 无法恢复的会话专属 Pair 丢弃并按策略重选；
- 保留用户 shortcut/theme 等无关偏好。

### Workspace

首次引入时不自动把所有最近文件变成 workspace。Workspace 是用户显式保存的可选工件。

### Cache

所有旧 cache key 缺少 SourceKey/revision/provenance 时，升级后直接失效，不冒险复用。

---

## 回滚策略

每个阶段在发布前定义：

- 可恢复的旧 settings；
- feature flag 是否可关闭；
- 新 schema 是否向后可读；
- provider/renderer 失败时的旧 Ready Session；
- 发生 crash 的原子文件；
- DB/cache 是否可安全删除重建。

对语义 V2，建议先保留旧 schema 的读取，不再写旧 schema；稳定两个发布后再删除读取路径。

---

## 总体完成条件

本路线完成不是以“文件拆小了”为准，而是以行为为准：

- Reference、Timeline Master、Pair 身份不再混淆；
- QML 不拥有媒体时钟和 range loop；
- 连续前后逐帧都不丢中间帧；
- Scrub 快速且 Commit 精确；
- 多候选不同时解码全部；
- Comparison 有 domain/provenance/metric；
- 所有 ViewModel 只拥有明确能力；
- CI 能以测试、trace、pixel capture 和性能数据证明这些结论。
