# 13｜风险登记、完成定义与项目治理

## 核心结论

这次整改最大的风险不是“功能做不完”，而是架构迁移期间出现双重真相、兼容层长期不删除、性能改善没有基线、或新分析能力给出不可解释的结果。因此必须用风险登记、阶段退出条件和严格 Definition of Done 管理，而不是只用任务完成百分比。

---

## 一、风险分级

```text
Probability: Low / Medium / High
Impact: Low / Medium / High / Critical
Exposure: Probability × Impact
```

处理策略：

- Avoid：改变方案避免；
- Mitigate：通过设计/测试降低；
- Transfer：交给明确 adapter/vendor boundary；
- Accept：记录失效条件与监控；
- Block：未解决前不进入下一阶段/发布。

## 三、阶段性风险控制

### 阶段 0

主要风险：观测代码改变时序。

控制：

- trace 默认内存有界；
- 开/关 trace 性能 A/B；
- 不在 worker 热路径同步写盘；
- trace 丢事件时记录 dropped count；
- baseline 保存 exact SHA。

### 阶段 1

主要风险：新旧 Pair/Reference 双真相。

控制：

- authoritative 只选一条路径；
- 旧路径只读投影；
- debug parity；
- renderer payload 同时记录 SourceKey 与 slot；
- 每个迁移 PR 删除一部分旧写入口。

### 阶段 2

主要风险：ViewModel 过度拆分。

控制：

- 以业务 capability，而不是每个属性一个类；
- 高频/低频边界；
- façade 稳定；
- property notification contract tests；
- 不引入 service locator。

### 阶段 3

主要风险：播放状态机重构造成陈旧事件/命令终态回归。

控制：

- 先抽 transaction object；
- model-based event permutation；
- 一次迁移一个 workload；
- old/new trace compare；
- range/step hardware gate。

### 阶段 4

主要风险：预览与 authoritative frame 混淆。

控制：

- 类型分离；
- Preview badge；
- Commit ACK；
- cache key revisions；
- 独立 worker优先级。

### 阶段 5

主要风险：指标数值正确但语义错误。

控制：

- ComparisonDomain；
- Exactness；
- Provenance；
- reference implementation；
- missing/unavailable 独立状态；
- export manifest。

### 阶段 6/7

主要风险：范围膨胀。

控制：

- N 源先逻辑管理；
- HDR/audio/codec 独立 ADR 与 release；
- 每项必须不破坏专业核心门禁；
- 不捆绑“通用播放器重写”。

## 四、Feature Definition of Done

任何单个功能/修复完成必须满足：

### 4.1 问题与契约

- [ ] 有明确用户现象或能力目标；
- [ ] 有已知事实/推断分离；
- [ ] 有可证伪预期；
- [ ] 状态 owner 明确；
- [ ] 输入、输出、失败、取消、关闭语义明确；
- [ ] 资源上限明确；
- [ ] 不变量与失效条件明确。

### 4.2 实现

- [ ] 改动落在批准边界；
- [ ] 无新增双重真相；
- [ ] async identity/revision 完整；
- [ ] stale result 明确丢弃；
- [ ] command terminal exactly once；
- [ ] GUI/render 不阻塞；
- [ ] 队列/cache/worker 有界；
- [ ] 旧 Ready 状态可回滚；
- [ ] telemetry/diagnostics 可定位。

### 4.3 测试

- [ ] 原问题失败测试；
- [ ] happy path；
- [ ] cancellation；
- [ ] failure；
- [ ] duplicate/late/reordered event；
- [ ] boundary values；
- [ ] historical regression；
- [ ] property/model/fault（适用时）；
- [ ] UI/accessibility（适用时）；
- [ ] hardware/pixel/perf（适用时）；
- [ ] soak（生命周期改动时）。

### 4.4 迁移

- [ ] settings/workspace schema；
- [ ] cache invalidation；
- [ ] old API consumer 搜索；
- [ ] feature flag 删除条件；
- [ ] downgrade/rollback 说明；
- [ ] release notes。

### 4.5 审查与证据

- [ ] Architecture Gate；
- [ ] Root-cause Report；
- [ ] Implementation Manifest；
- [ ] Independent Correctness；
- [ ] Regression/Edge；
- [ ] exact SHA evidence；
- [ ] 未验证项明确；
- [ ] 文档与代码同步。

“代码已合并”不等于 Done。

## 五、工作包 Definition of Done

### P0｜Comparison Semantics V2

完成条件：

- `Reference` 与 `TimelineMaster` 是独立领域字段；
- `ActivePair` 使用 SourceKey；
- session Pair 不再保存为全局 ordinal；
- legacy settings 有确定迁移；
- UI 角色标签清楚；
- Pair switch 保持 media time；
- source reorder/remove/replace 不错配；
- renderer slot 只在 presentation boundary；
- 旧 DifferenceEdge 业务路径删除；
- hardware Wipe/Diff 全绿。

### P0｜State Ownership Split

- façade 能力指向真实窄 ViewModel；
- `ReviewController` 不再同时服务 playback/alignment/notifications；
- Main.qml 无 range loop/Pair normalize/状态字符串业务；
- 高频 frame 更新不重建低频模型；
- QML/UI model architecture gate；
- 所有行为 parity；
- 兼容 adapter 删除或有明确最后期限。

### P0｜Navigation/Playback V2

- 显式 continuity policy；
- forward/reverse 连续无缺帧；
- Reverse Window 有界；
- Range 内核原生且不越界；
- command terminal 0 error；
- event permutation通过；
- hardware perf/soak通过；
- QML 不拥有媒体时钟。

### P1｜Scrub/Thumbnail/Status

- Begin/Update/Commit/Cancel；
- preview 与 authoritative 分离；
- unseen thumbnail；
- latest-wins/stale rejection；
- playback pressure 降级；
- Timeline keyboard/Accessible；
- Status Rail 统一；

### P1｜Comparison Analytics

- domain/exactness/provenance；
- CPU reference；
- GPU/SIMD differential；
- current/range/sequence；
- missing 不数值化；
- worst frames；
- per-source stats；
- JSON/CSV evidence；
- background priority；
- analysis cache identity/atomicity。

### P2/P3｜媒体扩展

每个 codec/HDR/audio 功能独立满足：

- descriptor/probe；
- exact mapping；
- hardware/software fallback；
- fixture；

## 八、范围控制

每次规划评审都用三个问题：

1. 这项功能是否强化“帧准确、多源同步、可解释比较”；
2. 是否依赖尚未完成的 P0 语义/状态整改；
3. 是否有可验证的退出条件。

不满足第 1 项的通用播放器功能通常后置；依赖 P0 的不得绕过；没有退出条件的不得开工。

建议维护：

```text
Now: P0 semantic/state/playback
Next: Scrub/analytics/UX
Later: HDR/audio/codecs/workspace/signing
Not now: network/DRM/media library/plugin ecosystem
```

## 九、兼容层与技术债清零规则

每个临时 adapter/flag 必须在创建时记录：

```text
owner
reason
introduced commit
consumers
removal condition
latest removal milestone
test proving safe deletion
```

CI 报告过期项。以下情况阻断发布：

- 已满足 removal condition 仍保留；
- 新功能继续依赖 deprecated path；
- 双写状态无 parity assertion；
- 临时 flag 默认长期关闭但无人负责；
- 文档把兼容层写成目标架构。

## 十、风险接受模板

确实无法立即解决的风险必须这样记录：

```text

```

禁止“以后优化”“已知问题”而无 owner/触发条件。

## 十一、停止/回滚条件

实施中出现以下情况，应停止扩大改动并回到最近稳定批次：

- stale/partial FrameSet 无法在最小测试解释；
-新架构需要第二个 authoritative event loop；
- Reverse/Scrub 资源不能有界；
- Pair/SourceKey migration 无确定规则；
- GPU/CPU metric 无法对 reference；
-关键硬件性能显著退化且无机制解释；
-兼容层数量持续增加；
-同一问题连续用 sleep/threshold 放宽处理；
-旧 Ready Session 回滚丢失。

回滚不是失败，而是防止错误方向扩散。

## 十二、最终项目验收会议所需材料

不是演示幻灯片，而是证据：

1. 目标架构与 ADR；
2. 问题→根因→测试→修复对照；
3. exact release SHA；
4. 不变量结果；
5. Pair/Reference/Timeline 迁移结果；
6. forward/reverse/range/scrub trace；
7. pixel/metric reference；
8. 多 GPU 性能；
9. Soak 资源趋势；
10. package/upgrade/signing；
11.开放风险及其失效条件；
12. evidence bundle hash。

最终判断标准：**用户能稳定地知道自己在看什么、比较谁与谁、当前帧是否准确、结果在哪个域成立；系统则能以测试和 trace 证明不会因异步、拓扑或性能优化破坏这一事实。**
