# CompareStation 收尾后分阶段改进计划

日期：2026-10-17。状态：待实施计划；本轮仅编写文档，不修改产品代码。

本计划按颜色可信度、常用素材兼容性、已有流程闭环三个重点推进。先固定数据口径与验收样本，
再交付受验证的 SDR 颜色显示，同时开展依赖已满足的兼容性与流程修复。每批独立验收，
不要求全部扩展完成后才能交付已有能力的修复。

当前工程收尾结束、建立可复现基线后才启动本计划。阶段表示依赖顺序，不承诺日历工期。
文中的验收条件是未来完成标准，不是当前软件已经通过的成绩。

主力电脑是日常生活与工作设备。后续执行默认不在该机自动启动完整回归、可见窗口测试、
GPU 性能门禁和长时间 lint/编译；先落实下面的测试环境分离。环境未就绪时保留对应待验状态，
不把门禁退回主力桌面，也不降低原有验收标准。

## 主力电脑使用约束与测试环境分离

此项是实施前置条件，归入 BASE，不新增产品功能。先迁移运行位置和改变执行频率，
再开展后续工作；本计划文档本身不修改 workflow、runner 或系统设置。

### 测试分层与运行位置

| 层次 | 内容 | 默认运行位置 | 触发时机 |
|---|---|---|---|
| 轻量静态检查 | 文档链接、脚本解析、与修改直接相关的快速契约检查 | 主力电脑可执行；纯读取且不启动 GUI | 文档或对应脚本改变时 |
| 开发定向验证 | 当前修改直接影响的小样本单元/组件测试 | 已确认不弹窗的窄范围可在主力电脑执行；其余走独立环境 | 有行为修改或失败需要复测时 |
| 完整软件回归 | 全套测试、完整 C++/QML lint、Debug/Release、样式与 DPI 矩阵 | 普通 Windows 云端 runner 或独立 Windows 测试机 | 一批修改稳定后，按原门禁要求执行 |
| 可见窗口验收 | 主窗、弹窗、焦点、鼠标、截图、解压包 GUI smoke | 独立 Windows 交互桌面 | 相关界面批次稳定后 |
| GPU 与物理显示验收 | D3D11VA、稳态性能、真实显示器颜色和跨屏 | 符合现行协议的专用 Windows GPU/显示环境 | 相关批次最终验收与发布门禁 |

部分组件测试会创建真实主窗；测试属于“单元/组件”分组不证明它无窗口或低负载。
执行前按具体测试核对，不能把 `Images`、`Ui` 或 `MainQmlContractTests` 整组默认当后台任务。

### 环境交付与验收

- 建立测试清单，记录会否弹窗、是否需要交互桌面/GPU/物理显示、典型时长与资源负载、
  可运行环境及适用门禁。首轮测量在独立环境进行，主力电脑不承担自动试跑。
- 核对现有 workflow 的路由。`build-test.yml` 的 Windows Debug/Release 与 `quality.yml` 的
  native-quality 仍选择 self-hosted 标签；硬件 workflow 也选择 self-hosted GPU 标签。
  “已交 GitHub Actions”不等于离开主力电脑，必须验证实际接单机器身份。
- 普通软件任务优先迁移到兼容的云端 Windows 或独立测试机，验证锁定工具链、依赖缓存、LFS、
  打包与测试环境后再切换路由。现有 Linux/core 检查可继续提供反馈，但不替代 Windows UI 验收。
- 主力机器不自动接收重型或桌面任务。路由用专用标签/runner group 等方式明确隔离，
  加入能检测误路由的检查；不能只给旧 runner 改显示名称，仍让其匹配重型任务标签。
- 首批迁移验收须证明：在主力机不接单时，修改能在指定环境完成对应检查；日志记录实际 runner，
  一次普通提交不会在主力桌面启动窗口。此处检查须有正反例及固定检查数，不能漏掉 workflow。
- 只允许使用主力电脑时，先完成不启动测试进程的代码/文档工作与轻量检查；完整回归或 GUI/硬件
  任务保留待验。需要在主力机执行时，使用用户明确允许的独占测试时段和事先列出的测试范围，
  不自行推断“现在空闲”或自动安排夜间运行。
- 同机不可避免的构建与非性能定向测试采取保守并行、较低优先级并串行使用同一构建目录；
  `-TestJobs 1` 只控制测试并行，不是 CPU/内存总限额。缓存或进程调度措施不得伪装成完全隔离。
- 最小化、第二显示器、虚拟桌面或同机 VM 不能作为资源隔离证明；VM 可承担适配过的普通测试，
  不自动取得 D3D11VA/真实呈现或物理色彩验收资格。性能正式采样仍按原优先级与硬件协议运行。
- 先定向验证，批次稳定后再执行完整门禁；结果绑定提交、diff、依赖和构建配置。相同输入的成功
  结果不重复跑，相关输入改变后重新判断影响；不能用缓存结果掩盖新的代码或环境变化。

退出条件是执行位置、路由和触发规则可核验。若只具备普通云端环境，可以先交付基础修复并明确
待验范围；物理显示和硬件能力的最终承诺仍等待合格环境，不从生活电脑强行补齐。

## 阶段 0 建立可复现基线

### BASE 构建身份与任务样本

**范围：** 记录提交 SHA、工作区差异、GUI/CLI 与 ZIP 哈希、依赖清单、Windows、GPU、驱动、
显示器及刷新率、DPI、系统 HDR/Advanced Color 状态、显示器配置文件。保存当前行为和耗时，
不在这个步骤扩大支持范围。

**依赖：** 当前收尾成果已确定；能取得合法的真实素材和可重复生成的小样本。
完整与桌面验证另依赖上述环境分离，不在主力电脑自动采集基线。

**验收标准：**

- 每个样本记录哈希、来源或生成方法、容器/编码或图片格式、位深、Alpha、颜色声明、预期用途。
  自动化夹具放在仓库测试目录；真实大素材和一次性证据放在 `out/verification/`，不复制测试套件。
- 图片至少覆盖 RGB8、RGBA8、透明区非零 RGB、灰阶、16-bit 低位差异、PNM、有效/缺失/损坏 ICC；
  视频覆盖既有三编码及 AV1/VP9 调查样本，包含 CFR/VFR、B 帧、8/10-bit、明确不支持的 HDR。
- 建立四条可重复任务：日常打开；A/B 局部比较；记录后重开；导出后独立重读。
  当前失败、未测、环境跳过分别记录，不把零项执行当通过。
- 频率来自真实任务清单；未取得频率时使用条件式优先级，不声称某种格式是用户最常用。
- 每项结果包含构建与素材身份。首个预览、完整数据就绪分别计时；旧候选成绩不转移到新包。

**退出条件：** 同一构建、同一输入和步骤能重现当前支持结果与主要断点，随后才比较改进效果。

## 阶段 1 固定像素与颜色口径

### COLOR1 分开保存分析数据与显示结果

**范围：** 将文件颜色信息、解码转换缓冲、分析输入、显示派生结果、导出语义分开描述。
RGBA8 与转换后 RGBA64 sidecar 保持既有采样含义；归一化浮点只改变读数格式，
不能被称为线性光、HDR 或新的精度。先做等价迁移，再引入颜色显示转换。

**依赖：** BASE；保留现有类型化接线试点成果。缺陷状态关联台账 I-02、I-05、V-05，
不把本计划工单编号另建为一套缺陷状态。

**验收标准：**

- 用固定样本逐字节比较迁移前后分析缓冲、RGBA/Alpha 探针、复制文本、原有 8-bit 和适用的
  16-bit 统计；重采样后仍不能声称像素级 16-bit 对应。PNG 样本输出按解码像素和 manifest
  语义核对，不要求编码文件字节完全相同。
- 数据契约明确区分文件原始码值、解码转换值、屏幕显示结果；未持有原始平面时不得标为原始值。
- 颜色显示设置、差异增益、背景切换不改变既有分析输入与统计；含透明隐藏 RGB 的样本不得丢值。
- 新的转换与缓存保留素材代次、请求身份和颜色配置身份；替换/取消/跨屏后，迟到结果不能覆盖新状态。
- 为“错用显示缓冲做统计”和“漏检旧代次结果”各提供能触发失败的反例；相关断言可共用反例。

**退出条件：** 等价迁移证据与数据契约成立，颜色功能尚未启用时没有数值口径回归。

### COLOR2 固化颜色样本与独立参考

**范围：** 把现有颜色样本设计落成小型真实编码夹具、生成脚本与 manifest。
覆盖 sRGB、Display P3、Adobe RGB、无配置、损坏/不支持配置、透明边缘和高位深渐变。
区分“相同码值、不同配置”和“不同码值、相同预期颜色”两类图片对。

**依赖：** BASE、COLOR1。参考结果不得由待测转换实现现场生成。

**验收标准：**

- 每个样本记录配置文件哈希、渲染意图、输出目标、参考工具和版本、参考值的生成方法；
  参考来源与待测实现独立，若共享同一引擎则另补解析可知的锚点，不能自证正确。
- 在选择颜色引擎前固定每样本的参考值和数值容差；精确拷贝/Alpha 必须逐位一致。
  有量化或色域映射的颜色样本按各自误差来源设定容差并解释依据，不在看到失败后放宽。
- 检查两类图片对能区分颜色配置被忽略、被重复应用和被错误继承；坏配置必须触发预定回退。
- 样本检查器断言样本总数、必需类别、哈希和实际检查次数；删掉一类样本或参考字段必须失败。

**退出条件：** 参考 manifest、容差和反例固定；颜色引擎选型有可执行判据，不凭依赖名称决定。

### COLOR3 独立呈现颜色状态

**范围：** 颜色说明脱离“格式转换到 RGBA8”的徽章条件。区分有效配置但未应用、已验证转换、
无配置的明确假设、损坏/不支持配置、显示环境未验证；A/B 分别显示。保留现有格式与精度标签。

**依赖：** COLOR1 的状态字段；COLOR2 的正反样本。

**验收标准：**

- 原生 RGBA8 带 ICC 时也能看见颜色处理状态；未转换、回退与未验证不能显示为已色管。
- 开图、只换一侧、对调、关闭、加载失败、快速切换后，标签与当前已提交素材身份一致。
- 信息在普通窗口和最低支持窗口尺寸可读，不要求悬停才能知道“颜色尚未验证”。
- 文案、工具提示和复制/导出的数据说明使用同一状态来源；有针对真实主窗接线的行为测试。

**退出条件：** 用户能判断读数是什么、显示受何限制；不把新增标签当作 ICC 已实现。

## 阶段 2 交付受验证的 SDR 颜色显示

### COLOR4 图片配置解析与 SDR 显示派生

**范围：** 首批处理支持范围内静态 RGB/灰阶图片的 SDR 配置。以 COLOR2 的同一组参考比较
Qt 与 Little CMS 等候选，再记录选型 ADR。解析和转换属于适配器，外部库类型不得进入核心。
首批配置类别、渲染意图和回退规则须在实现前列成支持表；不支持的类别显式回退。

原图观看采用颜色转换后的显示派生结果；探针、差异和统计保持 COLOR1 的解码缓冲口径。
Alpha、单通道和差异图是诊断视图，必须单独定义颜色编码与显示方式，不能把它们当原照片
再次套用来源 ICC。编辑副本和另存继续使用既有数据语义，颜色显示开关不悄悄改写素材。

**依赖：** COLOR1 至 COLOR3；COLOR2 的容差冻结；QML 主窗真实服务接线。

**验收标准：**

- 所有首批支持样本满足冻结的参考与容差；同码异色、异码同色样本均按各自预期处理。
- 颜色显示开→关→开时，原始分析缓冲、探针、复制颜色及差异统计逐位不变。
- Alpha 保持不变；透明边缘在黑、白、中性棋盘格上检查。明确背景合成空间与预乘边界，
  完全透明像素的隐藏 RGB 在分析数据中保留。
- 有效/无配置/坏配置的切换与取消不会继承上一素材的配置；转换失败保留已提交画面并说明状态。
- 后台转换不会阻塞 GUI/渲染线程；缓存按来源和颜色状态失效，有工作集上限和取消验证。
- 另存结果重读后符合既定位深、Alpha 和颜色元数据策略；未承诺保留的元数据明确列出。
  不把“显示正确”扩写成“编辑、另存完整保留原始精度”。

**退出条件：** 文件到显示派生的数值路径可验证；此时尚不能单凭数值测试承诺物理显示正确。

### COLOR5 Windows 输出与跨屏验证

**范围：** 先完成 Windows SDR 桌面的显示输出契约，确认窗口目标显示器、配置文件和
Qt Quick/D3D 输出解释，避免系统与应用重复转换。系统 HDR/Advanced Color 开启时检测并提示
未验证状态，不在本阶段实现 HDR 内容或色调映射。

**依赖：** COLOR4；有真实显示设备和明确配置的 Windows 环境。

**验收标准：**

- 支持表写明经过验证的 Windows/显示配置/输出路径；覆盖普通 SDR 与可取得的广色域配置。
  若某类设备不可取得，只限制对应声明，不用另一台设备的截图代替。
- 同一窗口跨显示器、运行中切换配置、睡眠唤醒和系统显示模式变化后，重新计算或显式降级，
  不继续展示旧环境的“已验证”状态。
- 数值参考、渲染输出与物理显示环境分别留证；输出空间与系统行为可解释，检查重复转换。
  缺少仪器时不声称显示器已校准或达到某个物理色差指标。
- 显示环境变化不会改写分析缓冲、统计、当前比较对、视口位置或正在恢复的素材身份。

**退出条件：** 首批可承诺的 SDR 显示范围明确，其余环境可识别、可回退、无错误成功标记。

## 阶段 3 补齐常用素材与已有流程

### MEDIA1 验收现有格式并收敛入口契约

**范围：** 优先验收已有 PNG/JPEG/BMP/GIF/WebP/TIFF/PNM 路径及 H.264/HEVC/MPEG-4 Part 2，
覆盖真实文件而非仅注入 QImage。GIF/WebP/TIFF 识别不扩写为动画、多页或序列播放支持。
对 HEIC/AVIF 等回退路径先测实际包，再决定明确支持还是明确拒绝。

**依赖：** BASE、COLOR1、相应真实编码夹具；关联台账 I-03、V-04。

**验收标准：**

- 支持表分别列出可打开、可显示、可精确比较、可导出的组合和已知转换；容器与编码分列。
- 每类受支持文件验证普通打开、拖入、替换、文件夹发现；Explorer 和默认关联按既有产品范围验证。
  多入口使用一致规则，未支持的入口必须给原因，不能只扩展文件过滤器。
- 验证尺寸、方向、Alpha、位深、颜色状态；PNM 覆盖 P1 至 P7 与 `.pam` 实际入口。
- 损坏、超限和不支持文件有清晰结果，失败/取消不替换原会话；越过现有尺寸和工作集上限时
  明确拒绝，不放宽上限掩盖缺少大图能力。
- 干净解压包重跑代表样本，证实实际打包插件/解码器可用；更新媒体支持说明中的陈旧基线。

**退出条件：** 用户能依据当前包的支持矩阵判断常见素材，不依赖碰巧安装的系统组件。

### MEDIA2 按真实需求扩展 SDR 视频和现代图片

**范围：** 视频优先评估 AV1/VP9 的 8/10-bit SDR 组合，逐个编码交付；图片按 BASE 记录的
实际缺口选择 AVIF 或 HEIC 等单个格式，不能把二者或全部变体作为一项笼统承诺。
RAW、PSD、SVG 不在首批默认范围。

**依赖：** MEDIA1、COLOR1；选定格式的解码、像素归一化、颜色和部署契约。
广色域输入可以先明确标为颜色未验证；宣称色管显示须另通过 COLOR4/COLOR5。

**验收标准：**

- 每个新组合都有真实样本，验证载入、seek/逐帧、双源比较、精度标签及适用的导出；
  视频覆盖 VFR/B 帧等实际存在的变体，不支持的变体保留明确拒绝。
- 软件解码是独立的可验证路径；硬件路径另验，不以有解码器或硬件标志证明可稳定播放。
- 保持完整 FrameSet、异步身份和 256 MiB 解码帧缓存限制；新路径的关键行为有针对性变异证据。
- 新格式入口、探测、文件夹、部署和说明一致；HDR 仍不得绕过准入后误当 SDR 显示。
- 任何新增依赖有许可、运行时清单和相对前一 ZIP 的逐文件增量说明；不搭带工具与无关运行时。

**退出条件：** 一个格式组合的真实工作流完成后再标支持；新格式不必与完整颜色功能同批发布。

### FLOW1 恢复图片问题的同一观察状态

**范围：** 补齐已有问题记录恢复：同一图片/文件夹行、比较模式、缩放和平移、分割方向与比例，
以及影响观察的通道、背景、差异增益、重采样和 Alpha 过滤设置。新增字段按需扩展记录契约，
不强制升级或重写旧记录。旧记录缺字段时明确部分恢复。

**依赖：** COLOR1；现有来源身份检查、异步图片载入和事务提交；来源参见
[主窗恢复分支](../../src/ui_qml/qml/Main.qml) 与
[问题记录契约](../../src/application/include/dvs/application/IssueRecord.h)。

**验收标准：**

- 在文件夹非首行、非默认模式、放大和平移的局部记录，关闭后恢复；字段及映射的图像位置一致，
  不能默认打开第一对。跨窗口尺寸/DPI 按图像坐标验收，不要求物理屏幕坐标相同。
- 只有正确素材提交成功后应用视图；快速连续恢复、取消、换会话和迟到结果不能串到别的素材。
- 文件移动、内容修改、同名异路径、缺图和解码失败走现有身份核验或重定位流程；不静默恢复错图。
- 恢复失败保留上一已提交任务，明确哪些状态未恢复；恢复成功不能隐含“原显示环境也已恢复”。
- 保存→读回→恢复端到端覆盖新旧记录；删去恢复字段应用或身份检查的变异应被检出。

**退出条件：** 保存的问题可回到同一素材和观察区域；部分恢复与完整恢复有可验证的区别。

### FLOW2 闭合截图 样本和片段的交接

**范围：** 优先验收现有三种输出：带标注显示结果、协议约束的精确 PNG 样本与 manifest、
时间线规范源的流拷贝片段。统一说明来源、位置、精度和颜色语义，不合并成一个含糊的“无损导出”。
先完善源身份与结果提示；任意候选源选择和精确视频重编码不是本工单的隐含扩展。

**依赖：** COLOR1；现有 IssueRecord、SampleExport 和 ClipExport 链路。
若截图捕获启用色管后的显示结果，额外依赖 COLOR4/COLOR5 的输出编码与标注契约。

**验收标准：**

- 从三源比较切换 GT、候选和直看后导出，UI 与结果清楚标出实际源；固定规范源行为不得被误标为
  “当前看到的源”。记录请求区间、实际起点与已知结束限制，重新打开核对实际首尾。
- 非关键帧/B 帧/VFR/非零起始 PTS 样本验证流拷贝边界，不把标记区间宣称为精确成片边界。
- PNG 样本重新解码并核对输入帧、GT、预测、裁剪和 manifest；颜色/精度明确为转换值，
  协议不完整或规划不成立时拒绝，不四舍五入换成另一帧。
- 截图明确是显示结果，跨软件使用所需的编码/颜色声明有契约；不把显示截图当原始像素证据。
- 失败、取消、已有目标和写入中断不发布半成品、不破坏旧输出；每次发布前读回当前暂存结果，
  防止消费旧文件。事务性与数据完整性有定向反例。
- 接收方仅凭输出及其标注/manifest 能确定来源与位置，并能按既有可用方式重新定位；
  暂不承诺搬移源文件后的便携问题包。

**退出条件：** 每一种输出都可独立重读、解释并追溯，既有能力不再停留于按钮可点击。

### FLOW3 单目录图片连续查看

**范围：** 在已有单图查看基础上，打开后列出父目录并支持手动上一张/下一张。
它与双目录同名配对是不同任务；首批只做当前目录、自然排序、手动切换，复用可用外壳，
不引入媒体库、递归扫描、自动轮播或新的多图模型。

**依赖：** MEDIA1、FLOW1 的来源身份及事务规则。此项是计划中的有限扩展，
排在既有恢复和交接修复之后，不阻塞这些修复先交付。

**验收标准：**

- 从文件选择、拖入或 Explorer 打开单图后，当前项正确高亮；自然排序覆盖数字、大小写、中文名称。
- 上一张/下一张的首尾行为固定为禁用并给出边界；坏文件保留当前图并提示，允许继续手动导航。
- 快速切换、目录刷新、删除、重命名与载入取消，不把旧解码提交给新项。
- 未保存编辑有一致的离开处理；浏览不改写原文件。进入普通单图导航不会意外替换另一个双图
  配对任务的某一侧；任务切换时先明确离开哪种工作流。
- 窄窗、快捷键焦点和帮助一致；首图与完整数据就绪分开测，不能用模型测试代替真实主窗操作。

**退出条件：** 连续查看一组普通图片无需反复打开对话框，双目录比较与编辑行为没有回归。

## 阶段 4 集成验证与交付

### RELEASE 验证当前包而非版本名称

**范围：** 将本批支持范围、代码、自动化证据、物理环境证据与实际 ZIP 对齐。
更新产品目标、现行台账及媒体支持说明；不把本计划改成第二份验收状态表。
按测试分层在独立环境执行，主力桌面测试须遵守已明确的使用约束。

**依赖：** 本批选定工单完成；后续独立扩展不作为阻塞条件。

**验收标准：**

- 编辑期间用窄范围测试，核对注册名与实际运行数量；稳定后完整测试、format-check、lint 各执行
  一次。失败先修复并复测失败范围，修正稳定后再做最终门禁；成功且输入不变时不重复跑。
- QML 样式、弹窗、布局或 DPI 变更跑完整相关矩阵，留真实窗口截图；颜色路径另保留数值、
  输出链路和显示环境证据，不用截图替代色彩正确性证明。
- D3D11VA 上双/三源 1080p60 连续五分钟，按现行协议排除预热与 seek/暂停区间；完整帧组丢失
  不超过 0.5%，seek P95 不超过 500 ms，UI 响应不超过 100 ms，解码帧缓存不超过 256 MiB。
  其他已配置的发布门禁照常保留，不因本计划缩减。WARP 不替代真实硬件。
- 新增颜色转换也检查 GUI 响应和工作集，不能只通过小色块数值测试；超出机器能力时有真实状态。
- ZIP 逐文件核对 runtime/资源/许可，使用干净解压目录及隔离的运行环境重测代表素材和入口；
  实际包必须包含所需解码器，不能借开发机 PATH 上的插件通过。
- 记录未执行、跳过与失败；硬件缺失时可以继续独立修复，但不能把相应性能/颜色声明标为通过。
  2.5.0 曾跳过本地物理门禁的授权不自动延续到后续发布。
- 验收证据绑定提交、diff、素材、二进制及 ZIP 哈希；输出读回后才发布或供下一步消费。

**退出条件：** 本批选定能力在同一发布候选上通过适用的软件、硬件和包体验收，支持说明与
已验证范围一致；任何未完成门禁和受限环境都显式保留，不能借版本号复用其他构建的成绩。

## 测试入口与证据要求

实现阶段使用现有 PowerShell 7 wrapper，不硬编码工具路径。以下仅为执行入口，先核对
当前 CTest 注册与计数，再按真实变更缩小范围；同一构建目录的 build/lint/test 串行运行。

| 工单 | 首要验证入口 |
|---|---|
| COLOR1 至 COLOR4 | `StillImageDecoderTests`、`ImageReviewControllerTests`、图片差异测试、真实 `ImageWorkspace` runner、`MainQmlContractTests`；新配置/转换测试放入现有对应层 |
| COLOR5 | 上述数值回归、平台输出检查、Windows 物理显示与跨屏人工验收 |
| MEDIA1/MEDIA2 | `MediaProbeTests`、`SoftwareDecoderTests`、`MultiSourceFrameProviderTests`、`StillImageDecoderTests`、入口/文件夹/打包检查 |
| FLOW1 | `IssueRecordTests`、`IssueRecordRepositoryTests`、`IssueLogControllerTests`、主窗恢复契约、真实图片工作流 |
| FLOW2 | `SampleExportPlannerTests`、`SampleExportWriterTests`、`ClipExportPlannerTests`、`ClipExportWriterTests`、相应控制器/主窗入口 |
| FLOW3 | 现有图片目录模型与主窗测试，按实际归属补行为覆盖；不预设一定复用双目录配对模型 |

定向测试示例：

```powershell
pwsh tools/build/build.ps1 -Preset dev -Test -TestRegex 'ui.(ImageReviewControllerTests|IssueLogControllerTests|MainQmlContractTests)'
pwsh tools/build/build.ps1 -Preset dev -Test -TestRegex 'media.(MediaProbeTests|SoftwareDecoderTests|StillImageDecoderTests|SampleExportWriterTests|ClipExportWriterTests)'
pwsh tools/build/build.ps1 -Preset dev -Test -TestGroup Images -FullMatrix
```

批次稳定后的软件门禁：

```powershell
pwsh tools/build/build.ps1 -Preset dev -Test
pwsh tools/build/build.ps1 -Preset dev -Target format-check
pwsh tools/build/build.ps1 -Preset dev -Target lint
```

真实硬件和 ZIP 门禁沿用 [构建指南](../building.md)、[runner 说明](../self-hosted-runner.md)
及仓库 AGENTS.md。domain/application 改动继续满足 80% 行覆盖要求。变异证据针对异步身份、
完整帧组、时序、缓存限制、数据完整性等改变的关键行为；低风险文案与布局用行为和视觉检查。
任何一次性检查脚本都断言检查数量，缺样本、缺锚点或零项匹配必须失败。

## 首批交付与后续决策

首批必做 BASE、COLOR1 至 COLOR3、MEDIA1、FLOW1、FLOW2；它们优先让已有能力可解释、
可复现、可交接。COLOR4/COLOR5 是颜色主线的下一批，完成即独立交付；MEDIA2 按真实素材频率
选择首个格式，与颜色显示可交错实施。FLOW3 排在既有闭环修复后，可单独交付。

只有下列条件出现时才扩大范围：

| 后续候选 | 启动条件 | 独立验收重点 |
|---|---|---|
| 任意区间精确视频输出 | 实际交接反复要求严格首尾帧，PNG 样本/流拷贝无法满足 | 输出源选择、精确首尾、帧率/时间戳、编码及颜色损失、事务发布；先定输出契约，不建设完整编辑器 |
| 更多现代/专业图片格式 | BASE 记录到反复中断且首批解码回退不能覆盖 | 每格式的位深、Alpha、方向、颜色和打包；RAW/PSD/SVG 不按扩展名合并承诺 |
| HDR 与色调映射 | 有稳定真实素材和可验收的 HDR 显示环境 | 独立颜色/精度/输出契约与物理显示验证，不混入 SDR 支持 |
| 超大图瓦块加载 | 实际常用素材持续越过当前尺寸或工作集上限 | 原图精度、局部取样、取消、缓存与工作集；先实测再决定架构 |
| 四视频源 | 明确存在三源不能完成的实际任务 | 完整帧组、布局、硬件预算与性能，不作为赶超 ICAT 的数量目标 |

图片三图/四图、音频、字幕、完整滤镜/转码面板、媒体库和 OCR 不进入本计划的默认交付范围。
ICAT 的共同任务对照可用于验证操作成本；Avidemux 用于比较裁切输出语义；GuoheView 用于
代表格式和颜色样本对照。竞品比较不替代项目自身验收，也不设未经实测的胜负或速度倍数。
