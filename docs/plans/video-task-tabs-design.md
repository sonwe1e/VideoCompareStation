# 视频任务标签契约

实现于 `9640b52`（2026-10-24），2026-10-25 对照 `VideoTaskHost` 与 `Main.qml` 整理。
本页保留身份、路由和恢复协议；原实施清单及逐轮记录从Git历史读取。
产品决策为[D-024](../engineering/decision-register.md)，真机缺口见[台账TASK-01](../engineering/visual-review-backlog.md)。

## 0. 单运行时边界

一个标签是一项审查任务：单视频或2–3路比较。`ReviewRuntime`/`ReviewController`仍各一套，
仅当前任务解码。后台标签保存状态记录，切回需要重开/定位，不能复制每标签一个播放器。
图片标签各有`ImageReviewController`与驻留像素；视频标签不照搬图片的资源持有方式。

## 1. 所有权

`ui_qml::VideoTaskHost`持有任务列表、身份匹配、活动项、标题模型和不解释的`QVariantMap`快照。
`Main.qml`采集/重放视口与播放状态，`ReviewShellController`沿用打开意图队列，组合根注册宿主。
后台不运行分析；窗口级偏好仍归原所有者，不新建第二套协调循环。

## 2. 任务身份

### 2.1 匹配与记录

- 打开前按规范化绝对本地路径、大小写不敏感匹配；合法媒体入口先经过现有URL验证。
- key为素材身份多重集＋参考源身份，顺序无关。AB与AC不同，单A与AB不同，同组不同GT也不同。
  匹配后沿用已保存槽位顺序，不采用这次打开的新排列。
- 成功打开后保存冻结来源身份（路径/大小/修改时间），用于会话变化与GT跟踪，
  不能拿冻结指纹代替打开前的路径匹配。源文件变化后重开失败必须点名报错。
- 三源内切AB/AC/BC只改比较对，不拆任务。追加/移除来源使原标签就地演化，不删旧建新。

### 2.2 打开提交

`openTask`复用已匹配任务或建立loading记录；最多12项，拒绝超过三路的单任务。
新任务只有成功终态才提交会话事实；新开失败移除loading记录，聚焦已有失败保留原记录。
宿主记录与当前实际运行时来源必须分别校验，不能只看标签的`activeIndex`。

## 3. 快照内容

快照在任何重开前采集，入口为`captureVideoTaskSnapshot`。

| 状态族 | 保存/恢复约定 |
|---|---|
| 素材与角色 | 源URL槽位顺序、参考槽、canonical槽；跨任务重开不映射上一任务时间 |
| 位置 | 当前帧与媒体时间；帧用于定位，越界/失败显示部分恢复 |
| 对齐 | 模式与手动偏移；不保存自动分析结果或手动锚点 |
| 播放 | 倍率、入出点及其时间、区间启用、循环、往返；切回始终暂停 |
| 比较 | 当前比较对、视图模式、差异类型/增益/过滤与阈值开关/数值/策略、指标阈值 |
| 视口 | 中心、缩放、ROI、分割方向与比例 |
| 直看 | 冻结来源身份；瞬态按住预览不保存，不按当前槽位猜旧身份 |
| 文件夹 | 全局目录的URL及行高亮；仅当目录仍匹配时恢复高亮，不触发打开 |

chrome/检查器显隐、OSC模式、快捷键方案、连续性策略为窗口或全局偏好。
来源显示排序/选中不是独立持久化标签配置。单视频跨重启续播记忆沿用原机制，
不等于保存任务标签；标签本身不跨重启。

## 4. 切换协议

### 4.1 暂停与替代

`beginVideoTaskSwitch`取消旧在途切换，暂停，再快照当前运行时实际所属任务。
新的切换替代旧切换，不排成长队；目标loading/restoring时拒绝重复操作。

### 4.2 同组快速路径

目标与运行时的槽位顺序/参考身份相同则只聚焦视频工作区，不重开、不推进epoch，
保持现有任务状态。不能把“素材集合相同”误用为运行时槽位也相同。

### 4.3 重开与终态

跨任务调用`ReviewController::reopenSourcesWithoutMapping`（preserveDisplayedTime=false）。
同任务内追加来源、改参考或替换仍沿用其既有保位置语义。
等待提交时绑定的打开命令ID/epoch终态；成功后核对URL并锁定新sessionEpoch。
来源或epoch再变则取消恢复。旧任务的命令完成不能推动新任务状态机。

### 4.4 比较对、模式与定位

`advanceVideoTaskSwitch`先提交保存的比较对一次，并写回保存的模式；等待匹配的比较对终态。
这是恢复路径，不触发“用户显式选对从全组模式回落”的交互逻辑。
之后提交快照帧seek，等待命令完成、目标帧就位且`framePending`解除；零帧/已就位无需重复seek。
越界或拒绝定位记录部分恢复。整个协议不调用play。

### 4.5 展示状态与结束

`finishVideoTaskSwitch`恢复视口、分割线、差异参数与指标阈值，然后区间（先shell镜像后内核命令）、
对齐/偏移、倍率、冻结身份直看、同目录行高亮。清理恢复上下文，显示完成或具体未恢复项。
新手动导航或另一任务切换可以取消在途恢复，不能让迟到状态写回别的任务。

### 4.6 失败与时间边界

- 重开失败：保留原会话和任务，报错点名目标文件，不悄悄清空画面。
- 比较对/定位失败：保留目标任务及已恢复部分，显示部分恢复。
- 总deadline为15秒，超时停止余下恢复并提示；它是兜底，不是体验达标线。
- `PairMetricsController`继续按会话/源/对齐身份丢弃旧批次；标签化不放宽已有异步身份门。

### 4.7 自动播放

切回已有标签始终暂停；空格继续。首次侧栏换片/打开的自动播放，以及启动请求的
`OpenForPlayback`偏好沿用原行为，不能与恢复协议混用。

## 5. 打开路由

| 操作 | 任务行为 |
|---|---|
| 文件菜单、普通拖入、启动打开单视频或比较组 | 经宿主新建/聚焦；2–3路保留参考源确认 |
| 再开同一任务 | 聚焦且保留进度；同素材组不同参考不合并 |
| 加入当前对比、移除一源 | 原标签演化，仍最多三源；同任务拓扑变化沿用保位置逻辑 |
| 侧栏点选、上一项/下一项 | 当前单视频就地换片；当前比较任务则新开单视频，保留原比较 |
| 侧栏明确“在新标签打开” | 使用显式新任务路由，不把当前单视频就地替换 |

打开失败只回滚本次候选，不推进列表到失败素材，不丢失上一个已提交任务。
图片未保存编辑的离开/关闭规则仍由图片工作流处理，不能被视频入口绕过。

## 6. 标签交互

标题为单视频文件名、双源`A ↔ B`、三源`A + 2`，悬停完整路径；同名附父目录消歧。
加载/恢复状态有明确提示。视频/图片标签分工作区显示，不做统一顶层媒体库。
关闭活动标签优先选右邻、末尾选左邻；关闭最后视频任务按现有路由回图片工作区或空态。
关闭素材与关闭整个任务是不同动作，源身份稳定后才执行移除。

## 7. 资源

应用解码池仍为224 MiB，后台任务不复制解码器、缓存或指标分析。
任务记录本身随标签数增长，不能宣称总内存完全恒定；真正需验证的是解码资源不按标签倍增。
切回冷seek和指标重采样的代价需要真实D3D11VA证据；不为掩盖延迟默认加每标签预取。

## 8. 快捷键

`Ctrl+W`关闭当前任务，`Ctrl+Tab`/`Ctrl+Shift+Tab`循环切换当前工作区的任务。
两工作区条件互斥，菜单/帮助来自`ShortcutCatalog`，在途打开/恢复继续遵守禁用与替代规则。

## 9. 验证入口

`VideoTaskHostTests`覆盖身份多重集/参考、上限、关闭邻居、失败与快照；
`MainQmlContractTests.VideoTabs*`覆盖主窗中的标签路由、快捷键和恢复行为。
关键反例是旧epoch/命令终态不得串任务、跨任务不映射上一位置、重开失败保留原任务、
比较对恢复不触发全组回落、同任务追加不拆标签。
既有变异证据在`out/verification/video-tab-identity-gates-mutation.ps1`，只属于对应批次。

## 10. 待验证

当前候选的三源切回P95、解码资源随标签数量的变化、设备换代稳定性、倍率恢复与指标
重采样开销仍需复验。500 ms是既有冷seek门限，不自动成为整个任务切回的新产品门限。
窄窗/高DPI标签可读性、文件夹全局导航体验也保留台账待验状态。

## 11. 已记录的选择

首版采用15秒总deadline、12标签、全局文件夹导航、两工作区分栏、顺序无关的素材多重集＋参考身份、
同标签原地组演化、不保存自动对齐结果/手动锚点、不提供复制任务、不在后台分析。
15秒恢复兜底与全局文件夹体验仍是待真实反馈复核的假设；其他新选择不得从旧提案的问句推导授权。
