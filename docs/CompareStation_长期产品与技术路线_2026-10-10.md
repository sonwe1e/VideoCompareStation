# 1. 成功标准与范围

## 1.1 不以功能数量定义“超越”

截至规划日，NVIDIA 官网展示 ICAT 0.6.17；官方介绍包括最多四路图像/视频比较、同步分屏、双源滑动覆盖、对齐、裁剪、循环、缩放和平移、播放速度调节。更新记录也涉及 Web 导出。[S1][S2]

因此，分屏、Wipe、循环和 Web 导出只能列为基础比较能力，不能列为独有创新。未在 ICAT 文档中看到的能力标记为“待实测核查”，不直接写成“不支持”。

本项目的超越目标有四个：

| 维度 | 应解决的实际问题 | 可验证的成功表现 |
|---|---|---|
| 观察效率 | 在三个画面之间找同一处缺陷很费力 | 同时间、同坐标、同尺度；局部框选与模式切换不丢观察位置 |
| 诊断可信度 | 不知道顿感来自素材、模型还是播放器 | 分开报告时间戳、应用调度、系统呈现证据与内容异常；不能确认时明确未知 |
| 实验可复核 | 换了模型、软件版本或文件就找不回原来的问题 | 问题记录能恢复来源、帧、ROI、协议和显示口径，并检测素材变化 |
| 数据生产能力 | 发现问题后还要到外部工具重新抽帧、裁剪、配对 | 从问题直接得到帧精确、成组一致、含配方和来源信息的训练样本 |

**产品北极星任务：原速播放发现武器拖尾 → 标记并框选 → 查看 GT/A/B 与相邻帧 → 保存证据 → 导出正确配对的样本。**

## 1.2 主线范围

主线保持 Windows x64、本地离线优先、1—3 路视频、原始 60 fps 降帧再恢复 60 fps 的插帧实验、常见游戏/手机录屏和图片审查。1080p60 为核心性能基准；已有 1080p120、小尺寸 10-bit 正确性覆盖保留，不用 4K/8K 指标驱动架构。

不安排音频、字幕、影视媒体库、完整非线性剪辑、通用 Photoshop、云协作平台。长期增加模型数量时，优先以同一 GT 分批比较，而不是先增加到八路同时解码。

## 1.3 已有能力与新增能力必须分开

主线文档已经记录 FrameSet 原子发布、时间线主源与 GT 角色分离、三源/参考焦点/四格布局、联动 ROI、Wipe、Diff、对齐和缺帧语义。[R2]

当前图片编辑接口已有裁剪、缩放、画布填充、翻转、90° 旋转、画笔、矩形填充/清除、马赛克、标注、撤销和另存副本。接口存在不等于所有交互都已逐项真机验收；阶段 0 负责核销。[R4]

新增重点不是再次实现这些按钮，而是：

**插帧协议、同位置工作流、时序证据、成组数据变换、帧精确导出、可复用分析与受控实验。**

# 2. 产品组织：三个任务状态，共享一个观察上下文

## 2.1 主界面

保留一个主窗口，提供“观察 / 诊断 / 样本”三个任务入口。它们是同一会话的工作状态，不是三个各自维护时间轴和素材的独立程序。

**观察状态**：大画布为主体，常驻源身份、比较对和精简走带条。侧栏沿用当前文件夹、历史和问题记录。高级指标默认收起。

**诊断状态**：继承当前时间、ROI 和源身份，按需展开相邻帧条、时序证据和局部运动图。没有新增输入时，不要求重新打开视频。

**样本状态**：显示前输入帧、中间 GT、后输入帧以及可选标签；右侧为变换配方，底部明确输出尺寸、有效区域和导出目的地。

图片查看和图片比较仍可直接打开，不需要先创建项目。数据配方和问题包是可选文件，不恢复此前移除的强制项目保存流程。

## 2.2 交互约束

- 一次用户意图只走一条动作链；菜单、快捷键、鼠标操作共享同一动作定义与启用条件。
- 模式切换不能改当前帧、GT、ROI、播放状态或采样口径，除非该动作明确要求。
- 有未提交编辑时，切换素材不能静默丢失；提供保存副本/保留编辑/明确放弃的最小决策。
- 视频中的空格仍表示播放/暂停；图片的 A/B 操作按工作区明确标注，不让新快捷键覆盖文字输入。
- 自动隐藏只隐藏辅助控件；当前源身份、异常数据不足、错位警告等关键信息不能因鼠标不动而消失。
- 颜色之外还用文字/图形区分 GT、模型、缺帧和未知状态；兼顾 100%、150%、200% DPI。

**技术**：现有 Qt Quick/QML、ReviewActions、ShortcutCatalog 与会话 facade；新增薄的任务状态/视图模型，不新增全局事件总线。

**验收**：连续切换三种任务状态，观察上下文不变；输入框有焦点时不误触播放；一次打开、切换和恢复均具有可追踪命令身份。

# 3. 基础可信性：先保证“比较的是同一件事”

## F01. 插帧实验协议与帧来源

**问题**：三个文件都标称 60 fps，仍可能有起点、裁剪、编码时间基或生成帧相位差异；只凭奇偶数猜生成帧会出错。

**实现**：新增可选 `InterpolationProtocol`，记录原始序列、降帧规则、保留帧相位、各输出帧对应 GT、两端输入帧、目标时间比例、首尾策略。优先导入训练/推理脚本给出的映射；没有映射时允许人工明确设置。自动匹配只产生建议，待确认后才改变映射。

内部保存整数时间戳和有理数 time base，显示层另行换算。未知帧来源保持 unknown；缺帧不补邻帧，不做自动时间拉伸来提高相似度。FFmpeg 的 AVFrame 明确区分 PTS、time base、估计时间戳和时长，可作为接入依据。[S3]

**技术栈与入口**：C++20 domain/application；现有 FrameTimeline、Alignment、MultiSourceFrameProvider；nlohmann-json。

**预期效果**：点击“下一生成帧”直接定位真正待评估帧；原速观看仍播放完整序列。保留帧可作为编码/转换基线，但不能自动认定其与原 GT 位级相同。

**验收**：对 60→30→60 的两种相位、60→20→60 的多个生成时刻、59.94、VFR、起点偏移、缺尾帧样例，映射与已知清单完全一致。UI 的 1 起计和内部 0 起计分别固定，导出含索引基准。

## F02. 色彩、像素和坐标契约

**问题**：RGB/BGR、有限/全范围、色度采样、Alpha 合成或显示缩放差异，可能被误判为模型缺陷；不同尺寸时“同一归一化坐标”不一定代表同一物体。

**实现**：保留三个明确的数据域：解码源域、统一分析域、显示域。记录位深、颜色矩阵、传递函数、范围、色度位置、SAR、旋转和实际转换；未知不填假值。原始源取值、规范化值和显示后取值不能混称。

同尺寸已配准图像使用像素坐标；不同尺寸/裁剪素材要有显式空间映射并标注重采样。GT 与候选使用统一显示变换；不能给每路分别自动对比度或各自拉伸差异图。

暂时不支持无降采样呈现的 4:2:2、4:4:4 或 RGB 路径，先显式警告，再按真实素材需求增加保真路径。分析/导出读取正确源域，不将 NV12/P010 显示纹理当作所有格式的原始数据。

**技术栈与入口**：FFmpeg 帧元数据和源平面、既有 D3D11/HLSL、ComparisonExactness、StillImageDecoder、ImageReviewController；Qt 色彩/图像接口按当前锁定版本验证。

**预期效果**：色差和边缘变化可以追溯到模型或转换步骤，不因显示链路的隐式处理而失真。

**验收**：RGB/BGR 色块、有限/全范围坡度、4:4:4 彩色细线、10/16-bit 渐变、Alpha 0/0.5/1、旋转/SAR、不同 DPI 固定金标准；差异增益只改变显示，不改变数值指标。

## F03. 播放预算、缓存和退化策略

**问题**：加放大镜、分析和 AI 之后，工具自身开始卡顿；扩大缓存又可能耗尽显存或占满硬解码输出 surface。

**实现**：复用完整 FrameSet，不为每个局部窗重新解码。缓存由字节预算和优先级驱动，明确区分前台帧、逐帧邻域、循环工作集和缩略图。先核对现有淘汰实现，不把“改名为 LRU”当作性能优化。

短区间预缓存必须先计算容量：1080p、NV12、三源、60 fps、2 秒，仅像素数据约 1.12 GB，未计对齐、解码 surface、差异结果等额外空间。预算不足时缩短窗口或只缓存局部；局部缓存不宣称全画面已就绪。

不能长时间固定住大量解码器自有 surface。必要时将帧复制到受控应用缓存，释放解码池引用；“多一次有界 GPU 拷贝”可优于“零拷贝但解码饥饿”。AVFrame 的引用计数与缓冲生命周期是实现约束。[S3]

实时观看允许显式丢弃整组过期帧并计数；完整审查保证不静默跳内容，但允许变慢并标注实际速度。两种模式都不补帧、不混帧。

**技术栈**：现有 SourceDecodeActor、FrameSetAssembler、FrameMailbox、D3D11 纹理池、字节预算缓存、C++ 有界队列。

**预期效果**：局部对比和分析不开第二套高负载播放链路；低配置机器退化可解释。

**验收**：三源持续播放、频繁定位、循环、开关 ROI、分析取消时内存不持续增长；源组绝不混帧；过载统计可复现。

# 4. 多视频与图片比较

## V01. 全景定位 + GT/A/B 同位置局部

**问题**：三路全景缩得过小，眼睛要在不同区域间移动，细小武器/人物轮廓差异难以确认。

**实现**：在已有参考焦点/四格布局上增加“全景 + 三个同 ROI 局部”的任务预设。手动框选一次，三路使用一个 ROI 变换；全景标出区域，局部支持 100%、200%、400%、最近邻/平滑与可选像素网格。保持现有全景并排，不用新预设替换全部视图。

在主画布上提供同步局部放大镜。放大镜只是一组已解码纹理的额外绘制，不创建新 decoder。第一版固定 ROI；后续跟随轨迹取自 GT 或指定参考，三路共用。各模型独立追踪、独立居中不能进入默认评价视图。

**技术栈**：Qt Quick 布局、ComparisonSurface、D3d11ComparisonRenderer、共享纹理 SRV、HLSL 采样；可选轨迹来自 OpenCV/离线 mask。

**预期效果**：一次定位后一直比较同一个部位，减少三屏视觉搜索。

**验收**：缩放、平移、切源、切模式后坐标保持；ROI 边界不被留白污染；增加局部窗不增加视频解码路数。

## V02. 全画布切换与受控盲比

**问题**：A/B 名称与左右位置容易影响判断，静态差异图也无法回答真实播放是否更自然。

**实现**：支持完整画布 A/B/GT 切换，保留同一播放时刻和 ROI；切换时所有参与源仍由同一帧组维护。增加同一短区间的顺序播放比较，原速优先。

后续增加可选盲比：隐藏候选名称、随机呈现顺序、保存随机种子、允许 A 好/B 好/无明显区别/无法判断。揭晓后仍能恢复原素材身份。禁止把播放中高频自动闪烁当作默认观看方式；手动切换用于静态定位，不代替原速判断。

**技术栈**：现有源选择与动作系统；C++ 受控试验状态；JSON 选择记录。

**预期效果**：对“哪个更自然”的结论有一致观察条件，而不只依赖看得更显眼的热力图。

**验收**：同一随机种子可复现顺序；切换不 seek、不改 GT、不改变显示增益；记录未作选择与平局。

## V03. 双参考差异与一致标尺

**问题**：A−B 差异只能说明不一样，不能说明谁更接近 GT；不同热力图自动缩放会放大视觉偏见。

**实现**：提供 GT−A、GT−B 的成对差异布局，锁定阈值、增益、颜色标尺、分析域与 mask。候选之间的 A−B 保留，但标题明确“候选差异，不代表质量优劣”。

连续帧中固定标尺，不逐帧自适应拉满。可显示误差较大的区域轮廓，但一键返回不叠加的原图。任何自动配准后的结果作为辅助视图，原始错位误差保留。

**技术栈**：既有 DifferenceEdge、ComparisonContract、PixelDifference/PairMetricsService、D3D11 差异 shader。

**预期效果**：同一颜色代表同一数值；不会把两个模型各自的小误差都拉成同样严重。

**验收**：切显示增益不重新改变底层统计；无 GT 不出现“更好”结论；缺帧/颜色不兼容时数值标记无效而非零。

## V04. 图片查看与编辑结果比较

**问题**：原图、工作副本和导出图片身份混淆；目前编辑和评分分离，若只替换显示图可能出现“看到副本、评分仍是原图”。

**实现**：保留现有原图只读规则。提供显式“将编辑副本作为候选比较”，生成新的图像身份和 revision，再进入比较管线；不要悄悄改变当前原始素材。

双图共享同坐标导航；RGBA、RGB、Alpha、棋盘格/深/浅背景可切换；单侧换图失败保留旧对。检查透明边缘时同时可见 Alpha 和合成效果，避免只看一张棋盘格图。

**技术栈**：现有 ImageReviewController、ImageEditController、ImagePairLoader；QImage、高位深 sidecar 和统一视图状态。

**预期效果**：能够验证裁剪/抠图/填充后的实际数据，而不是误看显示副本。

**验收**：编辑后比较的像素身份与分数一致；撤销/重做生成正确 revision；原始文件哈希不变。

# 5. 卡顿与内容异常诊断

## D01. 播放时序证据面板

**问题**：平均 60 FPS 并不能解释某一时刻的停顿；应用绘制 ACK 不能等同于屏幕真实呈现。

**实现**：用同一帧身份串联以下时间：源 PTS/时长、调度目标、decode ready、FrameSet ready、绘制/提交、可获得的系统 display 事件。使用 QPC/单调时钟记录，UI 只低频刷新摘要，不每帧输出大量文本。

证据等级分开：

| 等级 | 能证明什么 | 不能直接证明什么 |
|---|---|---|
| 源时间信息 | 文件要求的帧时序、重复内容候选 | 播放器按时显示了它 |
| 应用记录 | 解码就绪、调度延迟、完整帧组跳过、绘制/提交 | 屏幕已扫描输出该帧 |
| 系统呈现记录 | 支持路径下的 OS 呈现时间/状态 | 面板像素响应、人眼体验或所有显示路径均可观测 |

Qt 的 `afterFrameEnd` 表示场景图提交，不能据此命名为真实显示完成。DXGI 统计和 PresentMon/ETW 提供另一层证据，但受交换链、权限、系统路径与采集丢失等条件限制。[S4][S5][S6]

现有 ComparisonSurface 接入 QSGRenderNode，优先用公开 Qt 接缝记录应用事件、以独立 PresentMon 采集做验证；不能假定自有可调用统计的交换链，也不为一个统计面板先改写 Qt 渲染循环。[R6]

对 ETW 按进程/交换链/时间相关联，必要时加入自身 trace 标识。关联有歧义时只报告区间级证据，不伪造单帧对应。采集不可用、事件丢失、权限不足均显示未知，不显示“零丢帧”。高级采集是可选功能，不能要求以管理员身份启动基本播放器。

**技术栈**：C++ QPC、有界环形事件缓冲、Qt 信号、DXGI 能力探测、PresentMon Collection/ETW 的可选适配器。

**预期效果**：区分文件时序、应用赶帧、系统呈现和内容运动四类问题。

**验收**：人工注入解码延迟、渲染延迟、错误 PTS、重复内容；面板分类与注入点一致。60 fps 在 120 Hz 上正常显示两次不能被报成素材重复帧。59.94 与 60 的节拍差异不得由静默补帧掩盖。

## D02. 一键异常标记与时序检查卡

**问题**：发现一瞬间异常后难以定位；逐帧只看当前帧，无法判断是偶发还是生成帧周期性错误。

**实现**：在现有问题标记上增加“记录附近区间”，保存的是已呈现位置而非尚未完成的 seek 目标。打开诊断卡后显示 5—9 帧胶片条、生成/保留标识、同一 ROI 和已知输入端点。默认区间可调，不自动声称人按键的时刻就是缺陷精确时刻。

提供原速循环、前后逐帧和辅助慢放；循环接缝单独标记，自动异常分析不跨接缝运算。可在预算内预缓存并重新原速播放；报告缓存范围和呈现证据。低速只帮助拆解画面，不能作为原速流畅度验收。

**技术栈**：IssueLogController、现有 In/Out 状态与缓存、QML 虚拟化帧条、F01 的映射。

**预期效果**：从“刚才顿了一下”直接进入可复核的上下文。

**验收**：定位和恢复均绑定同一 session epoch；模型缺一帧时该格显示 Missing；胶片条不阻塞走带。

## D03. 运动位置/时间进度偏差

**问题**：生成帧存在，但目标位置过度接近前帧或后帧，形成停一下再跳的感觉。

**实现步骤**：

1. 先提供人工特征点/边缘锚点检查，并在 GT/A/B 同时显示该区域。
2. 对纹理可靠区域使用金字塔 LK；需要稠密运动提示时使用 OpenCV DIS。小 ROI、离线执行，置信度不足则不输出确定结果。[S7]
3. 有 GT 时比较生成目标与同一时刻 GT 的位置/轮廓及时间变化；如果用轨迹相位拟合，只在可稳定匹配的短区间执行。
4. 参考轨迹、mask 和有效区域由 GT/共同参考确定，不各自居中候选而掩盖位置错误。
5. 无 GT 时只给疑似不连续提示；真实加速、转弯、遮挡、重复纹理、运动模糊均可破坏简单假设。

示例仅用于说明：匀速合成点的 GT 为 `0→5→10`，预测 `0→1→10`，问题是中间运动进度错误。真实素材的中间时刻不必在几何中点。

**技术栈**：C++ application 调度；独立 OpenCV worker；共同坐标的特征点/轮廓数据；可选后续研究模型。

**预期效果**：给出“这一区域在生成时刻偏前/偏后”的空间证据，而不是只给一个总体 PSNR。

**验收**：匀速、加速、圆弧、静止、遮挡和重复纹理分别测试；自然加速不能一律被判错；不支持区域必须有覆盖率和未知标记。

## D04. 纹理残留、重影与局部停滞

**问题**：整体位置接近 GT，但武器边缘、头部、UI 局部还留在前一帧或后一帧位置。

**实现**：组合三类证据，而不是只计算生成图更像哪个输入：同一局部的输入/GT/预测；原坐标下的时间切片；GT 运动引导下的候选与 GT 残差对比。

时间切片先支持固定线或窄带，横轴为位置、纵轴为时间，GT 与候选共享色阶。残留可能表现为分叉/拖尾，但真实透明、模糊与遮挡也会出现类似图案，因此只是诊断证据。

后续可计算共同 GT 运动变换 W 下的时间残差：

`T = mean_M |(P_t - W(P_(t-1))) - (G_t - W(G_(t-1)))|`

其中 W 对两路完全相同，M 为共同有效区；错误/无效光流、镜头切换、遮挡区排除并报告比例。原始未补偿视图始终保留。该分数是项目待验证的候选指标，不是标准化卡顿分数，也不能直接判断是光流还是融合网络的根因。

**进一步接入模型中间结果**：允许训练/推理脚本按同一 FrameRef 导出两路光流（例如 t→0、t→1）、对应 warp 图、可选遮挡/融合权重以及细化残差。每份光流必须声明所在网格、方向、dx/dy 顺序、像素/归一化单位与采样约定；不能仅按两个通道就猜语义。界面按“输入 → 光流/warp → 最终输出 → GT”逐级检查，不要求播放器重新执行整个模型。warp 已错时优先排查流与采样链路，warp 较合理但最终图出现残留时优先检查融合/细化；这仍是缩小排查范围，不是单凭画面证明训练根因。不存在的融合权重不伪造，未提供中间结果仍可用基本诊断。

**技术栈**：CPU 参考实现、OpenCV 运动与图像处理；成熟后才将简单算子移入 HLSL；独立诊断结果模型。

**预期效果**：区别整体运动偏差与局部内容残留，保留明确的可见证据。

**验收**：前帧局部复制、后帧局部复制、双边缘叠加、正常运动模糊、半透明 UI、真实遮挡六类样本；不把“相似”直接判为“复制”。

## D05. 规整线条抖动与形变

**问题**：墙面瓷砖、地板接缝、楼梯边缘在生成帧中扭曲，整体像素误差可能不突出。

**实现**：允许画一条检查线/带，提取边缘及局部直线；对比 GT 的法向偏移、局部曲率和随时间变化。平面区域可使用 GT 的共同运动补偿，但同时展示未补偿误差，不对模型分别做几何校正后再评分。

镜头透视变化、实际弯曲纹理、运动模糊不满足直线假设时，退回人工检查，不把所有曲率都认定为缺陷。

**技术栈**：OpenCV 边缘/线段检测、C++ 几何统计、QML 叠加与时间曲线。

**预期效果**：专门找到规则背景结构中的局部波动，服务现有插帧训练问题。

**验收**：已知亚像素/像素级线条位移与波浪形变；真实透视 GT 不误报；所有几何读数标记原图像素单位。

## D06. 自动异常导航，而不是自动根因裁判

**问题**：长视频靠人工全看耗时；只按差异最大排序会反复出现同一个问题或正常镜头切换。

**实现**：分两级处理。低成本扫描检测时间戳、近重复、帧间误差突变与场景切换；高成本只复核候选 ROI 的运动/残留/线条。将邻近同一事件合并，按对象、缺陷类别和时间分散候选。

低变化检测不能直接等于异常冻结。FFmpeg freezedetect 以一段时间内的内容变化与噪声阈值判断，只适合作为一项候选信号。[S8]

标签区分“自动候选 / 人工确认 / 已排除 / 证据不足”。没有分析结果与没有发现异常是两种状态。候选队列同时保留随机样本，避免只查看模型已经怀疑的位置而无法发现漏检。

**技术栈**：现有 PairMetricsService 扩展的任务调度、C++ 轻量统计、OpenCV worker、JSON/可重建本地索引。

**预期效果**：少看重复的正常帧，把人工时间集中在值得检查的事件上。

**验收**：在按源视频隔离的留出集评估召回、精确率、每分钟误报与不可判比例；目标仅在校准后冻结。初始建议是前 20% 候选时间覆盖至少 80% 严重缺陷、候选精确率至少 70%，未达到则不进入默认自动工作流。

# 6. 指标与模型结论

## Q01. 从“单一总分”改为有口径的结果卡

**问题**：平均分掩盖少量严重问题；不同模型的有效样本、mask 和阈值不同导致比较不公平。

**实现**：固定三类结果：通常表现、变差比例/有效数量、已确认严重问题。中位数为观察项，不独自决定赢家；缺陷列表按类型组织，不用一条“最差时间段”代替问题证据。

对误差越低越好的指标，固定：`Δe = e_B - e_A`，正数表示 B 更差。指标名称、版本、方向、数值域和聚合规则全部保存。PSNR 则需另行标明越高越好，不能复用错误方向。

分别报告生成帧、保留帧和完整时序。统计对象使用共同 GT ROI/mask 与共同有效样本交集；来源不一致时拒绝直接排名。自动推断帧类型不能未经确认进入正式榜单。

阈值通过保留帧重编码对照、正常片段和人工标注进行校准；展示“数值变化”和“超过校准噪声范围”两层，不宣称阈值天然对应主观可见性。时间上相关的帧不能假装都是独立样本，区间估计按源片段进行分组抽样。

**技术栈**：复用 PixelDifference、ComparisonMetrics、PairMetricsService；复杂指标/统计在 Python worker，结果以版本化 JSON 回传。

**预期效果**：能回答“通常是否更好、明显变差是否增多、具体在哪里”，而不是只有一条平均分。

**验收**：A=B、局部恶化、少量严重恶化、大量轻微改善、缺 GT、零有效 mask 六类测试；N=0 显示无有效样本；阈值改变必须保留原始结果。

## Q02. 时间指标作为补充证据

**问题**：每帧分数相近，运动质量仍可能不同。插帧基准研究也指出仅看逐时刻误差不能充分说明时间一致性。[S9]

**实现**：先实现可解释的图像残差随时间变化，再验证 D03—D05 的分项指标；不直接把所有分数相加成“流畅度 92 分”。对 LPIPS 等有空间感受野的指标，不把任意 mask 乘黑背景后就冒称精确的目标级分数；明确 crop、边界和汇总方法。

若接入已有 VideoQualityEvaluation，首先交换统一的 source/frame/ROI/mask/metric 元数据与原始结果，不复制一套分割模型下载、阈值管理和指标语义。集成接口先于代码库合并，分别核验两个仓库后再提具体代码修改。

**预期效果**：数值能帮助导航和复核，不能掩盖明显的人眼缺陷，也不因模型更平滑就自动获得更高评价。

# 7. 数据集制作：从单张修图到整组可复现变换

## S01. SampleGroup 与配方执行器

**问题**：对输入图、GT、mask 分别裁剪或旋转，容易破坏训练对应关系；一次正确操作不能批量重放。

**实现**：定义 SampleGroup，至少包含前输入、GT、后输入，并可附 mask、光流、有效区域、模型输出和来源身份。把已有图像编辑能力逐步提取为“纯操作 + 参数”；QML 仅提交参数。预览和批量导出调用同一个配方执行器。

配方保存顺序、坐标基准、随机种子、算法版本、填充值、插值策略和适用对象。默认几何变换整组一致；“只退化输入、不改 GT”必须是明确实验模式。

多目标共享同一次几何变换的原则可参考 Albumentations additional_targets，但不能把其普通 image/mask 类型直接当成完整光流变换实现。[S10]

**技术栈**：C++ SampleGroup/TransformRecipe、现有 ImageEditController 接缝、QImage/专用高位深像素操作、nlohmann-json；Python 可调用同一规格的受测适配器，不另写一套不一致规则。

**预期效果**：预览一次正确的处理，能可复现地应用到整个样本或批次。

**验收**：同一输入、配方、固定软件环境输出一致；原文件不改写；同一视频派生样本保持相同数据划分身份。

## S02. mask、光流与有效区域的语义变换

**问题**：普通图像的旋转/填充规则并不能直接用于所有标签，错误标签可能比缺数据更有害。

**实现规则**：

| 操作 | 图像处理 | 标签处理 |
|---|---|---|
| 同区域裁剪 | 三帧用同一框 | 光流空间位置裁剪；终点出界需更新有效性；mask 同框 |
| 水平翻转 | 翻转像素 | 对应网格翻转，dx 取反 |
| 旋转/缩放 | 明确中心、插值与新画布 | 向量随几何线性部分变换，不能只旋转向量可视化颜色 |
| 填充/扩边 | 明确纯色、透明、边缘延拓策略 | 新区域通常标为无有效监督，不能凭补像素制造运动真值 |
| 任意内容替换 | 记录变动区域与新来源 | 重新计算已知标签或置为无效；保留合成来源标记 |
| 时间反转 | 输入顺序反转 | 必须有正确反向映射；不能简单将前向光流逐像素取负 |

一般端点变换规则：若原光流从 x 指向 x+f(x)，源与目标图分别由 T0、T1 变换，则：

`f'(T0(x)) = T1(x + f(x)) - T0(x)`

共同仿射变换 `T(x)=Ax+b` 下，才可简化为向量乘 A。实现需固定前向/后向光流、网格、像素中心和单位。

类别 mask 用最近邻；连续 Alpha/概率 mask 用单独连续规则，不能混用。补边、遮挡和采样无定义区域携带 valid mask。

**技术栈**：C++/NumPy 参考几何实现、专用 flow/mask 处理、属性测试；成熟后优化，不先写复杂 GPU kernel。

**预期效果**：增强后的数据仍然是正确训练样本，而不是仅看起来正常的图片。

**验收**：解析平移/旋转/缩放光流、非对称裁剪、出界、反向流、单像素目标；逆操作测试只用于理论可逆的变换，不要求有插值损失的操作位级逆转。

## S03. 选区、抠图、透明度与内容替换

**问题**：需要去掉对象、提取 UI 或合成特定区域，但边缘易残留原背景，透明值也可能错误。

**实现顺序**：先完整打通矩形/多边形/笔刷选区、导入 mask、加减选区、羽化、去边/背景检查和透明 PNG；然后增加可选 AI 分割。

SAM 3.1 可作为后续分割与多目标跟踪候选，官方发布记录提供了 Object Multiplex 信息；这不等于已证明 Windows 打包、你的五类对象和透明 UI 均适用。[S11]

AI 运行在可选独立进程；安装/权重由用户明确触发，锁定版本与哈希。Windows 原生环境先做验证，不把尚未验证的模型宣称为可直接 ONNX/DirectML 部署。未通过时保留手工/导入 mask 主线，不拖住基本查看与编辑。

必须区分分割 mask、Alpha matte 和干净前景 RGB。SAM 输出不能自动当成半透明 UI 的真实 Alpha；细边和透明度需要独立 matting/人工修边/已知透明素材。AI 内容修复只作合成数据，不能默认变成真实 GT。

**技术栈**：QML 选区交互、C++ 像素/选区操作、可选 Python/PyTorch/SAM 3.1 worker；matting 另立能力与验收。

**预期效果**：可处理训练相关元素，同时知道哪些边缘/透明度可靠，哪些是人工或模型估计。

**验收**：白色半透明 UI、黑背景残边、细武器、头发、孔洞、遮挡、Alpha=0 隐藏 RGB；AI 失败/缺权重时基本功能正常。

## S04. 可控运动的合成数据

**问题**：真实视频中的异常难以控制，无法知道某个失败到底对速度、透明度、遮挡还是线条敏感。

**实现**：建立轻量 2D 合成器，输入背景、RGBA 前景、运动轨迹和渲染参数，在精确 t0/t/t1 直接生成三帧。支持平移、旋转、缩放、加速、遮挡顺序、透明度变化和规则线条；模型不能参与生成其自身评估 GT。

先做无运动模糊、可解析运动的模板。加入运动模糊时按固定曝光窗口渲染多个子时刻，记录曝光和采样规则，不把单帧模糊当成完整物理模型。

合成空间、Alpha 方式和采样核明确记录；线性光合成与现有数据管线的数值合成作为不同配方，不能隐式混用。半透明前景与背景可能有多种运动，不能为混合像素伪造唯一的“完美光流”；可导出分层运动/权重或将单流标签标无效。

**技术栈**：C++ 可复现 CPU 参考合成器，必要时 OpenCV；确认数值一致后用 D3D11/HLSL 加速预览。配方 JSON 与样本导出共用。

**预期效果**：有目的地构造瓷砖抖动、UI 残留、武器重影和遮挡失败的测试/训练数据。

**验收**：已知整数平移与亚像素平移、角速度、遮挡时刻；GT 为同一场景的独立时刻渲染；合成与真实样本分开标记与报告。

# 8. 帧精确导出、批处理与复现

## E01. 从问题直接提取训练样本

**问题**：现有流拷贝裁剪受关键帧和解码依赖限制，不适合作为训练三元组的精确帧抽取依据。

**实现**：保留现有片段分享导出，新增独立 `SampleExportService`。它按 F01 的 FrameRef 精确解码/选择帧，按源像素 ROI 输出输入、GT、预测和标签；复用媒体层而不是采集屏幕。

三种输出明确分开：展示截图（可有标注）、审查片段（说明编码与边界）、训练样本（无 UI、不隐式缩放、完整来源和颜色转换信息）。PNG 可避免再一次有损图像编码，但 YUV→RGB 仍可能发生数值转换，不能称为源编码域位级原样导出。

每个样本先写临时目录并校验，完整后才发布；取消、空间不足、单帧错误不能留下看似完整的训练组。

**技术栈**：现有 libavformat/libavcodec 媒体层、Image encoder、C++ 任务调度、JSON manifest、原子文件发布。

**预期效果**：一次问题标记直接得到可投入数据流水线的、来源可追溯的样本。

**验收**：B 帧、长 GOP、VFR、非关键帧起点、首尾缺帧、不同源偏移；按固定解码/转换策略与独立解码参考比较；UI 标注绝不进入训练数据。

## E02. 批处理与可恢复任务

**问题**：手工操作可用后仍难处理大量素材；一次坏样本可能导致整批失败，随机增强不能复现。

**实现**：GUI 生成配置，CLI 执行相同应用用例；提供 dry-run、抽样预览、开始/停止、断点继续、逐样本状态与失败原因。按输入指纹、配方、随机种子和实现版本判定是否可复用结果。

初期 JSON 清单足够；只有检索/规模确实成为瓶颈后才加 SQLite 可重建索引，manifest 仍是交换和复现依据。不把数据库引入所有打开/播放流程。

随机数流按 sample_id 派生，避免改变 worker 数量或任务顺序就改变增强结果。GPU/AI 的跨硬件数值不承诺位级一致，应记录环境、模型哈希和允许误差；需要严格可复现的测试使用固定 CPU 参考路径。

**技术栈**：既有 CLI + C++ 应用服务；JSON；可选 SQLite；受控 worker 池。配置只允许白名单操作，不能通过配方执行任意代码。

**预期效果**：批处理和交互预览遵循同样的数据规则；中断可恢复，错误可定位。

**验收**：至少 10,000 个小样本的可恢复压力测试；注入损坏文件、磁盘满、取消和进程终止；成功/失败/跳过数守恒，无半成品冒充成功。

## E03. 问题包与模型版本回归

**问题**：模型更新后不知道旧问题是否修复，或者旧问题修了又出现新问题；别人的浏览器无法保证原生精确审查环境。

**实现**：扩展现有 IssueRecord，增加区间、插帧协议、采样/颜色条件、分析版本和确认标签。保留旧版读取与明确迁移；未知未来版本只读拒绝，不原地覆盖。

输出便携问题目录：JSON、必要的无损帧/ROI、缩略图、可选原生合成的对比视频和离线 HTML。HTML 负责阅读与分享，不宣称多个浏览器 video 标签天然帧精确同步；精确复核以原生软件和导出的逐帧数据为准。

同一固定问题集可导入新模型输出，恢复相同 ROI/mask/阈值，生成修复/退化/未变化/无法判定的结果。实验集合保存清单，不变成强制媒体项目。

**技术栈**：IssueRecordRepository、nlohmann-json、可选 HTML 模板、媒体导出服务；复用已有记录恢复事务化流程。

**预期效果**：每次模型修改都能回到相同问题进行验证，得到可解释的回归结论。

**验收**：原素材移动/修改/缺失、协议变更、mask 版本变化、旧记录迁移、部分恢复失败；不允许显示“全部恢复”但实际只打开了文件。

## E04. 数据谱系与训练/测试隔离

**问题**：相邻帧或同一录屏的多个裁剪进入训练集和测试集，导致评估过于乐观；重复/过期数据不易发现。

**实现**：记录 source_group_id、原视频身份、时间范围、父样本和配方；按源录制/场景组划分集合，再生成增强。相似检测可建议重复，实际合并/删除要显式确认。

快速检查可用尺寸/mtime；发布训练样本与正式报告时记录完整内容指纹，不能把文件路径当作永久身份。派生样本继承谱系及 split，不因换文件名就变成独立测试样本。

**技术栈**：JSON 谱系、SHA-256、可重建索引、CLI 校验。

**预期效果**：回归和模型选择基于独立数据，而不是重复素材。

**验收**：相同源不同名称、不同裁剪、邻接帧、同一配方多次导出；泄漏检查不自动删文件，报告明确冲突。

# 9. 技术路线与工程约束

## 9.1 选定技术栈

| 层 | 决策 | 选择理由与边界 |
|---|---|---|
| 主程序 | 延续 C++20、Qt Quick/QML | 复用现有架构与交互，不用 Electron/Python GUI 重写 |
| 视频输入/精确导出 | 延续 FFmpeg 动态库 | 统一时间戳、解码和帧选择口径；不额外要求用户配置 ffmpeg.exe |
| Windows 显示 | 延续 D3D11、D3D11VA、HLSL | 优先解决缓存、生命周期、时序和正确性，不先迁移 D3D12/Vulkan |
| 图像编辑 | 既有 QImage/高位深路径 + 纯变换算子 | 先抽已有操作，预览/导出共用，不另造完整修图引擎 |
| 轻量分析 | OpenCV 可选受控 worker | 先低成本、可解释的特征/线条/运动，再决定是否上研究模型 |
| AI | 可选独立 Python/PyTorch worker | 不阻塞启动、不成为播放依赖；崩溃隔离；模型锁版本 |
| 控制与数据交换 | JSON 配置/结果；有需要再共享内存 | 第一版不引入 gRPC/Web 服务；大图不走 base64 JSON |
| 数据存储 | manifest/recipe/issue JSON | 便携、可检验；SQLite 只作后期可重建索引 |
| 验证 | MSVC/CMake/CTest、GoogleTest、Qt Test、WARP + 实际 D3D11VA | Windows 本地执行；WARP 证明部分正确性，不能证明真实播放性能 |

具体 Qt、FFmpeg、CMake 与依赖版本继续以仓库锁定值为准，不为了规划升级到最新版本。新依赖引入时锁版本、列出分发许可和权重来源，再做升级决策。

## 9.2 实时路径与分析路径隔离

实时路径只做必要的解码、完整帧组装、显示和轻量计时。分析任务读取带身份的不可变帧/ROI 快照；磁盘扫描、内容指纹、模型加载、图像导出不在 GUI/渲染线程执行。

优先级遵循：交互控制与当前帧 > 连续播放 > 邻域预取 > 分析/导出。具体沿用现有优先级语义，改动前核对，不建立互相竞争的第二套调度器。

GPU 空闲不能作为天然保证。播放恢复时停止提交新的重任务，并以小批次限制在途工作；已经提交的长 kernel 不承诺立即可抢占。先做资源预算，再谈“后台不影响前台”。

共享内存只共享明确定义的 CPU 数据和生命周期；不能把当前 D3D11 纹理地址直接交给 Python。跨进程 GPU 共享属于独立后期验证项，不作为首版依赖。

所有异步结果含 asset_id、session_epoch、frame_ref、request_id、recipe/model/metric revision；旧会话结果不可覆盖当前画面。

## 9.3 技术债小步治理

不以文件行数为唯一拆分理由。在新增功能触碰范围内，先补行为测试，再抽离纯逻辑，最后接 UI；一次 PR 不同时改变状态所有权、线程模型和渲染后端。

优先提取四类接缝：插帧协议、时序证据汇总、样本配方执行、分析任务适配。PlaybackCoordinator 保持唯一播放状态权威；Main.qml 保持组合层；新的分析对象不成为第二个播放协调器。

新增模块名在实现前视为提案，不把计划中的类名写成当前已经存在的代码事实。

## 9.4 升级、安全与数据保护

原图只读，写操作显式目标目录，拒绝输入路径覆盖。导出先临时写入，清理仅限本任务创建内容。导入问题包校验路径越界、尺寸、数量与数据长度；不自动执行脚本。

AI 安装和权重下载显式触发，默认不联网、不上传素材。可选模型缺失只禁用对应能力。

每个能力可独立关闭；升级旧记录先保留原文件。发生失败时能回到原有比较/图片查看，不要求用户清空全部设置。

# 11. 验收体系：结果比新增按钮更重要

## 11.1 本地验证顺序

每个小步按以下顺序完成：纯逻辑测试 → 媒体/协议契约 → QML 交互 → Windows WARP 图像正确性 → 真实 D3D11VA 性能 → 用户任务走查。

不以“测试数量多”替代正确的场景。不依赖新增云 CI；沿用本地脚本。同一构建目录的 build/lint/test 串行，避免多个 AI 任务争用构建产物。

终端默认只打印必要摘要：构建 SHA/dirty、场景、实际执行测试数、通过/失败、身份错误、丢帧统计、延迟分位数、峰值预算、未验证项。详细诊断可留本地，不要求用户上传日志、ZIP 或结果文件。

## 11.2 固定数据矩阵

| 组 | 必须包含 |
|---|---|
| 时间与身份 | 60/59.94/VFR；两种保留相位；B 帧；长 GOP；缺帧/重复/首尾偏移 |
| 内容正例 | 整体运动错位；局部前帧/后帧残留；头部/武器局部缺失；线条波动 |
| 内容反例 | 正常静止、真实加速、镜头切换、运动模糊、透明叠加、遮挡和重复纹理 |
| 显示与数值 | RGB/BGR、有限/全范围、色度细线、位深梯度、Alpha、SAR/旋转、DPI |
| 数据变换 | 固定网格、解析光流、mask 类别、透明前景、出界/补边、时间反转 |
| 可靠性 | 快速连续 seek、切会话、关闭窗口、磁盘满、文件损坏、worker 崩溃 |

先建立小而确定的 30 个短片核心集；随后扩展校准/留出集。训练、阈值校准和最终验收按源视频分开，不能用同一批片段反复调参后宣称泛化。

## 11.3 建议目标

以下是工程目标，阶段 0 根据固定硬件与素材基线确认并冻结，不是已经达到的成绩。

| 指标 | 建议目标/判定 |
|---|---|
| 三源帧身份 | 编号帧、随机定位、切换和恢复测试中，错配为 0 |
| 样本身份与变换 | 控制样本上，帧/ROI/标签对应错误为 0 |
| 原始数据保护 | 原文件改写为 0；失败任务发布半成品为 0 |
| 稳态播放 | 固定支持配置上三路 1080p60 连续 5 分钟，应用额外跳过完整帧组为 0；系统呈现另行验证 |
| 1080p120 | 沿用已有 1—3 源一分钟门禁；缺相应显示器则记未验证 |
| 缓存内交互 | 候选切换 P95 ≤50 ms；相邻逐帧 P95 ≤80 ms，实测基线后确认 |
| 一般交互 | 非阻塞操作到首个可见反馈 P95 ≤100 ms；耗时任务可取消 |
| 新增显示开销 | 同配置稳态帧时不劣于冻结基线 10% 以上，且不能以丢帧换取更短时延 |
| 数据复现 | 固定 CPU 参考环境和配方重复生成一致；AI/GPU 跨环境差异按记录策略处理 |
| 任务效率 | 与 ICAT 的共同任务中，中位完成时间争取降低 ≥30%，错误发现率不能更差 |
| 自动导航 | 留出集目标：前 20% 候选时间覆盖 ≥80% 严重问题，精确率 ≥70%；同时披露 N 和误报 |

源 PTS、应用帧组跳过、系统显示事件三类计数各自报告，不能混成一个“Dropped frames”。测试要预先规定启动、主动 seek、循环接缝等排除区间，不在看到坏结果后临时排除。

## 11.4 与 ICAT 的公平对照

固定 ICAT 版本、CompareStation SHA、Windows/GPU/驱动、显示刷新率、素材、缩放、颜色设置和播放速度。共同能力比较加载、定位、局部观察、帧检查、区间重播与证据分享；新增能力比较完成整个插帧审查/样本任务所需的人工步骤。

交替工具使用顺序，控制学习效应；统计时间、错误、遗漏、点击/键盘操作数和恢复成功率。单个用户测量只能说明该用户/该任务上的改善；多人数据才能支持更广泛的体验结论。

# 12. 最容易走错的方向与替代做法

| 风险 | 不采用的做法 | 采用的做法 |
|---|---|---|
| 功能堆积 | 新增十几种模式、让用户自行组合 | 围绕观察/诊断/样本三项任务组织已有能力 |
| 自动诊断误导 | 给所有视频一个“卡顿分数” | 给证据、有效范围、候选标签和人工确认 |
| 工具改变被测内容 | 补帧、混帧、各路独立对齐美化 | 默认原样呈现，辅助变换明确标注 |
| 新功能造成卡顿 | 将模型推理放到播放路径 | 小任务、预算、暂停重分析、独立进程 |
| 大重构拖延 | 先重做 D3D12/Qt UI/插件平台 | 在现有核心中提取最小接缝 |
| 错误训练标签 | 光流作为普通 RGB 图片旋转 | 端点变换与有效 mask |
| 错误 GT | 把 AI 修复或插帧输出作为真实目标 | 标为合成/估计，GT 来源明确 |
| 虚假保真 | 屏幕截图当作原始训练帧 | 精确解码、显式颜色转换、无 UI 导出 |
| 范围漂移 | 转为通用播放器/修图/云平台 | 保持插帧视觉审查与样本制作主线 |

# 附录 A：建议的数据契约

以下为设计字段，不是当前已经实现的接口。

## A1. FrameRef

`asset_id`、`stream_index`、`source_frame_index`、`index_base`、`pts`、`time_base_num/den`、`duration`、`timestamp_origin`、`content_fingerprint`。

显示帧序号、编码器 decode 顺序与 presentation 顺序明确分开。估计时间戳带来源标记，不假装来自容器的原始值。

## A2. ReviewContext

源身份、canonical source、GT source、比较对、当前完整 FrameSet、alignment revision、ROI、空间变换、采样、颜色/分析域、显示增益、区间、协议 revision。

视图变化不是素材内容变化；缓存键分别包含真正影响结果的参数。

## A3. DiagnosticObservation

观察项 ID、关联源/帧/区间、证据等级、算法版本、数值/单位、有效区域和覆盖率、阈值版本、候选类别、人工状态、不可用原因。

不使用无定义的 `confidence=0.95` 伪装概率；未经校准的数值称为匹配/质量分数。

## A5. 进程任务协议

请求：job_id、job_kind、asset/frame/ROI 身份、输入文件/共享内存描述、参数版本、预算和输出路径。

响应：progress、result、cancelled、failed；每项都携带 job_id 和输入身份。参数只接受允许的算法和操作，不执行任意命令。文本控制消息用 JSON，像素用文件或经验证的共享内存，不用 base64 传整段视频。
