# 视觉质量审查：产品目标与工作流

更新：2026-09-22。需求来源：本次用户对视频、插帧、图片与透明度审查的说明。
本页区分**用户明确需求**与**建议方案**，不把设计提案当作已实现功能。
代码基线、工作区改动和问题定位见 [Agent 导航](../agent-guide.md) 与
[工程问题清单](../engineering/visual-review-backlog.md)；格式现状见 [媒体支持](../media-support.md)。

## 1. 用户明确的产品方向

CompareStation 是面向本地素材的开源视觉质量审查工具，用户计划免费、非营利地维护它。
核心任务是视频播放、视频对比、图片查看、图片对比。视频无需音频或字幕；
重点是观察模糊、重影、掉帧、插帧形变以及运动不流畅等质量问题。
不要因“播放器”这一名称而默认扩展媒体库、音频、字幕或复杂剪辑能力。

用户主要以产品目标表达需求；遇到技术约束，应解释其对观察结果的影响，
给出可行行为与验收方式，避免用实现术语代替产品讨论。

| 工作流 | 用户明确需求 | 建议采用的可观察验收结果 |
|---|---|---|
| 视频播放 | 常见压缩格式、流畅播放、跳帧/定位、快进、倍速 | 能定位指定位置并前后逐帧；超出机器能力时能看见播放状态，避免误判素材 |
| 视频对比 | 比较两个 Prediction 或 Prediction 与 GT；分割线、误差图之外，需要放大、拖动、高亮 | 在同一时刻、同一局部检查差异，切换视图后保留观察位置 |
| 图片查看 | WebP、PNG、JPG、用户称为“PPNM”的格式；通道值，尤其 Alpha | 能检查 RGBA 数值和透明边缘，知道读数是否经过格式或显示转换 |
| 图片对比 | 重视 Flicker、Fade、分割线；需要 GT、Prediction 1、Prediction 2 三图比较 | 可围绕同一 GT 检查两个结果，保持坐标与缩放一致 |

“PPNM”暂按 PNM 家族（PPM/PGM/PBM）记录，准确格式仍待真实样例确认。
用户提到 Flicker/Fade 好用，表达的是产品期望；不能据此认定当前代码已提供对应入口。
“跳帧”暂同时覆盖人工逐帧/跳转和播放追赶，界面与文档应区分二者。

## 2. 必须向用户解释的观察边界

这些是审查结果成立的条件，不代表需要一次实现所有专业功能：

- 素材自身重复帧、播放器因负载跳过画面、显示器刷新节奏是不同问题。
  播放器丢失呈现机会时，应报告**整组比较帧**的情况，不能只看单路平均 FPS。
- 正常速度观看用于判断运动节奏；逐帧完整审查用于检查每帧缺陷。
  当解码跟不上时，不能同时承诺原速、所有帧均呈现和低延迟。
- 帧序号相同不必然代表时间相同。30 fps 输入、60 fps Prediction 与 GT 比较时，
  需要明确按时间、按序号还是人工映射；不能自动补帧掩盖模型输出错误。
- 放大、显示转换、色度重采样或位深转换会影响观察。原始通道值与显示后取样应有明确标识。
  “可以打开”“可以流畅播放”“适合精确比较”应分别验证。
- 差异越显眼不等于质量结论越准确。Fade 自带叠影，Flicker 自带闪烁；
  无 GT 时只能说明两个结果哪里不同，不能单凭差异图宣称某个结果更好。

## 3. 建议的核心观察流程

以下为设计建议，尚未作为已完成实现或固定界面规范：

1. 打开素材并指定角色：GT、Prediction 1、Prediction 2，允许用户修改名称。
2. 正常播放发现异常；暂停后保留附近短区间，方便反复播放。
3. 框选局部，所有参与比较的素材同步缩放、平移和光标坐标。
4. 手动切换候选或使用分割线，必要时启用高亮、误差图、Fade/Flicker。
5. 查看前一帧、当前帧、后一帧，区分单帧失真与时间连续性问题。
6. 保存问题位置及观察条件，之后能回到同一状态复核。

| 建议能力 | 用途与限制 | 建议验收样例 |
|---|---|---|
| 播放状态 | 呈现实际速度、追赶/跳过情况，区分正常速度观看与完整审查 | 人为增加负载时可见状态变化；不能把播放器跳帧标为素材错误 |
| 局部联动 | 保持同一观察区域；100% 表示明确的像素映射 | 缩放后点击 100% 得到真实 100%；切候选时缺陷仍在原位置 |
| 阈值高亮与误差图 | 用固定标尺定位变化，阈值用于隐藏微小差异 | 两候选采用相同阈值、增益、色阶；局部误差不会因自动缩放色阶而误导 |
| 观察记录 | 保存素材身份、实际帧/时间、映射、区域、模式、转换与指标条件 | 重开记录可以复现观察，并辨别“原始数值”与“显示空间”结果 |

现有实现的入口可从 [ComparisonViewport.qml](../../src/ui_qml/qml/ComparisonViewport.qml)、
[TabbedInspector.qml](../../src/ui_qml/qml/TabbedInspector.qml)、
[PlayerOsc.qml](../../src/ui_qml/qml/PlayerOsc.qml) 查起；修改前核对主界面实际使用的组件。

## 4. 图片与 Alpha 优先级

用户特别重视把图片贴到视频或其他图片时的透明度表现。建议优先补齐完整观察流程，
而不是只在像素读数中增加一个 A 值。

| 建议模式 | 解决的问题 |
|---|---|
| 棋盘格、黑底、白底、指定背景 | 透明区域、黑白边、半透明合成结果 |
| Alpha 灰度图与 Alpha 差异图 | 遮罩形状、渐变及两图透明度差异 |
| 忽略 Alpha 的 RGB | 检查透明区域里隐藏的颜色 |
| 原始值与归一化值 | 明确通道位深，例如 8 位 A=128 约为 50.2% |
| Alpha 解释说明 | 区分直通/预乘 Alpha，避免直接相减导致错误判断 |

建议样例覆盖仅 Alpha 不同、RGB 与 Alpha 同时不同、完全透明像素内含不同 RGB、
半透明边缘贴黑白背景，以及高位深输入；检查数值与最终合成外观是否一致。
实现入口为 [ImageWorkspace.qml](../../src/ui_qml/qml/ImageWorkspace.qml)、
[ImagePairLoader.cpp](../../src/ui_qml/src/ImagePairLoader.cpp) 和
[StillImageDecoder.cpp](../../src/media_ffmpeg/src/StillImageDecoder.cpp)。

## 5. 三素材设计建议

三图比较是明确需求，具体布局还未定。建议共享“素材列表、参考素材、当前候选、视口状态”，
避免为第三张图继续复制双图专用状态。视频、图片共享产品概念即可，无需强行合并解码调度。

| 建议布局 | 适用任务 |
|---|---|
| 固定 GT，另一侧切换 Prediction 1/2，作为默认候选 | 保留足够大的画面，精看同一局部 |
| GT、Prediction 1、Prediction 2 三联 | 同时观察整体差异 |
| 两候选与各自对 GT 的误差图，可切回 GT | 比较错误位置和幅度；共享指标、阈值与色阶 |

后续可考虑“哪个候选在该指标下更接近 GT”的区域图，但必须保留误差定义与中性区域，
不将其呈现为自动主观质量裁判。区域指标、区间曲线、批量统计与报告也是后续建议，
不能因底层已有某个指标函数，就宣称端到端分析功能可用。

插帧审查可增加“只看生成帧”及前后帧条带；生成帧身份应来自用户指定规则或元数据，
不能默认奇数帧一定是生成帧。文件夹配对扩展为三文件夹、图片序列播放也属于后续提案。

## 6. UX 与待细化事项

用户明确要求界面容易上手。建议首屏直接提供四个工作流入口，常用工具保留并排、分割线、
切换、差异、局部放大；通道、阈值、精确性与对齐细节放入检查器。
适应窗口、100%、框选、重置应有可见按钮和操作提示，不能仅依赖隐藏手势。
优先复用已有缩放、区域、比较对和问题记录能力，工程位置见问题清单。

下列事项在对应功能落地时用样例或原型细化，常规修复可先按本文目标继续：

- “PPNM”的实际文件样例，常用编码、分辨率、帧率及目标机器决定支持矩阵和性能验收集。
- GT/Prediction 是否同帧率、同尺寸，以及生成帧规则，决定对齐和比较可用性。
- 三图默认布局以真实审查任务验证；HDR、高位深、色彩管理的范围按素材需求分期。
- 用户指定默认行为后，更新本页及对应工程条目，不把临时假设写成用户已批准的决定。
