# CompareStation 2.0.2

2.0.2 修的是 2.0.1 之后的两个用户可见故障：视频文件的右键菜单里出现**两个** CompareStation
入口，而且**点任意一个都报**「启动动作无法打开」，应用随后像卡死一样停在弹框上。本轮同时包含
一轮评审界面的视觉改版：比较语义没有变化——比较对、时间轴、对齐与差异指标的计算和判定都与
2.0.1 一致，改的是界面配色、排版和几个交互细节，没有新增或移除查看／对比能力。

## 主要变化

### 右键打开不再以「致命失败」告终

| 现象 | 原因 |
|---|---|
| 点右键入口弹出 `the requested startup action could not be opened.`，然后应用挂住 | 评审会话在图形设备就绪之前拒绝打开，而应用在**一个固定时刻**提交启动请求，把「被拒」当成致命错误：弹框 + 写日志 + 进程退出 |

会话是否就绪由场景图初始化的通知异步送达，提交点与它之间只有约 50 ms 余量（实测：场景图就绪
`+1422 ms`，提交 `+1576 ms`），胜负取决于调度。现在改为：

- 被拒且会话会就绪时，**每 50 ms 重试一次，上限 10 秒**；只有会话就绪之后仍然拒绝才算失败。
- 失败只写一条 `DVS_STARTUP_PROBLEM` 日志并输出到 stderr，**不再弹框、不再退出进程**——用户已经
  在看的窗口不会被关掉。
- 第二次启动转发过来的请求走同一条队列，实例正忙时它是被**接受**的，而不是让转发方以为失败了。
- 窗口改为在请求**被接受之后**才激活，被拒的打开不会再闪一个空窗口。

### 菜单里只留一个入口

右键菜单按文件关联链拼装，`HKCU\Software\Classes\.<ext>\shell` 与
`SystemFileAssociations\.<ext>\shell` 都在链上，任何一份遗留的同命令注册都会渲染出第二个同样
标题的入口。现在每次启动都会清扫这两个父键下**指向本命令**的 verb：

- 判定依据是**指向什么**——`ExplorerCommandHandler` 指向本命令的 CLSID，或 `command` 默认值里
  启动 `comparestation.exe`；一律不按键名判断，所以别的工具的 verb 一个都不会动。
- 自己的 verb 保留，清空后的父键按既有规则回收。
- `-Uninstall` 同样带走遗留副本；`RegisterExplorerCommand.ps1` 的注册与卸载两条路径都做同样的
  清扫，并输出 `stale_verbs=` 说明清掉了几个。

如果注册表是干净的而菜单里仍是两个，那是 Windows 11 把同一个 verb 同时画进新菜单和
「显示更多选项」，属于 shell 行为。另外，机器级（HKLM）的旧注册需要管理员权限才能清除，
应用侧无法自愈。

### 评审界面改用 slate 主题令牌

`VcsTheme.js` 现在把整套配色写成具名令牌：从画布到抬升面板的表面色、中性控件状态与带强调色
填充的选中态、拆成边框／填充／可读文字的强调色（填充按钮上的白字标签仍满足 AA 对比度）、成功
与警告族、画在画面上的半透明浮层底板，以及圆角令牌。源身份沿用应用图标——A 天空蓝、B 橙、
C 紫罗兰——由 `sourceColor`／`sourceBackground`／`sourceBorder` 统一提供，chip、徽标与画面
标签不再给同一个槽位配出不同颜色。

菜单栏、源条、比较栏、视口浮层、传输条、时间轴、缩略图弹窗、检查器、图片工作区、文件夹侧栏、
拖放确认对话框、空状态与快捷键浮层都改读这些令牌，不再各自写死十六进制颜色。

顺带修掉这几处一眼可见的问题：

- 倍速下拉框原本固定 58／68 px 宽，当前倍速被省略成「…」；改为按最宽标签计算宽度，并与旁边的
  连续播放开关等高。
- 传输条按钮改为与更高的播放键共用一条中心线。
- 时间映射读数原本是画在源标签上的红色边框横幅；现在是叠在源标签下方的中性底板，红色只留给
  真正的失败横幅。
- 分析徽标的精确度着色只在差异模式生效，并排查看不再出现假的警告色。
- 时间轴入出点区间的 alpha 写进颜色而不是 `opacity`，画在它上面的括号保持完全不透明。

### 原生标题栏与头部同色

Windows 上窗口向 DWM 请求沉浸式深色边框与圆角，并把标题栏底色与文字色设为头部背景 `#111722`
和正文色 `#f1f5f9`，标题栏与菜单栏读作同一个头部。不请求系统背板（Mica）：窗口本身画不透明
背景，背板不会透出来。smoke 模式跳过这次调用，UI 桥接改为链接 `dwmapi`。

### 通知栈取代四处浮层

Toast、意图队列、打开进度与拖放错误合并成舞台底部的一个通知栈，位于舞台控件之上、浮动传输条
之下，不再盖住头部工具栏。打开进度用中性色，不可用／不精确的差异状态归入警告族，红色只留给
真正的失败。

### 重新点击已选中的选项不再丢失高亮

Qt 会在 `onClicked` 之前翻转可选中按钮的 checked 状态，所以重复点击已选中的模式、工具或缩放
选项会让高亮消失，而实际状态仍是选中。`ReviewActionButton` 新增 `mirrorsState` 抵消这次翻转，
由调用方的绑定继续掌管选中态；六个互斥编辑工具改为单选菜单项，编辑模式只保留一个填充按钮。

### 被最小化的窗口会被还原

第二次启动把文件转交给正在运行的实例时，`activateWindow()` 原本只调用 `show()`／`raise()`／
`requestActivate()`，被最小化的窗口保持最小化，文件开在看不见的地方。现在它只清除最小化标记，
最大化和全屏保持原样；Windows 上首次显示与转交还会调用 `SetForegroundWindow`。

## 门禁

- 新增 `src/app/StartupRequestDispatch` 的 10 项单元测试，shell 注册套件新增 5 项（18 → 23），
  双击入口验收脚本 49 → **59** 项。
- 15 条新断言全部附变异证据：12 个变异体（8 个 C++、4 个脚本）逐一破坏一种行为并被对应断言抓住，
  控制组全绿。证据脚本 `out/verification/startup-repro/mutate.ps1`。
- 变异过程中还抓到一处**静默通过**：脚本用例的种键辅助函数原本用 `[string] $CommandLine = $null`
  区分两种形状，而 PowerShell 会把 `$null` 变成空字符串，于是实际种下的是一个清扫永远不会匹配的键，
  用例却因为「种下了、还在」而通过。改为 `[switch] -AsCommandLine`，并先读回验证种下的形状再断言。
- 修掉长期变红的 `quality.release-contract`：上一次发版把发布工作流的 `body_path` 改成从校验后的
  版本推导（避免第二个标签发布上一个版本的说明），而契约仍要求字面量，两者对不上；同时
  README 的升级链还停在 `1.2.0→2.0.0`。契约现在**接受字面量与推导两种写法**——两者的意图都是
  「发布的说明属于正在构建的标签」，推导形式更严格。
- 界面改版新增 `tst_review_action_button`（5 项，去掉 `mirrorsState` 后其中 3 项失败）与
  `MainQmlContractTests` 的编辑头部契约（编辑模式只允许一个填充按钮，回退即失败）。

## 已知限制

- 未在无头环境实测资源管理器里的实际观感；两个入口的复现依赖受影响机器的注册表实况，
  开发机上没有可复现的第二份注册。
- 机器级（HKLM）的遗留注册需要管理员权限清除。
- 18 个扩展名清单在仓库里仍有四份，没有跨份一致性契约测试。
- 本次发布物由本机构建，没有标签工作流产生的 CI 日志与硬件证据；下一次标签推送若恢复自托管
  runner，应以工作流结果为准。
