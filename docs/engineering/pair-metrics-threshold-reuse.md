# 视频指标：阈值／策略复用分析结果

日期：2026-10-01。基线 HEAD `4a67d1b`；第二批工作区实现，未提交、未发布。
上一批顺序采样的协议与证据见 [窗口调度性能报告](pair-metrics-window-performance.md)。

## 行为与边界

- 视频帧只做一次 `computeRgbAbsoluteAnalysis`：保存 RGB MAE／MSE／PSNR／最大误差，
  以及 LumaOnly、AnyChannel、AllChannels 各 256 个整数阈值的累计坏点计数。
  `metricsAt(threshold, policy)` 无需像素；Alpha 不参与任何指标。
- 保留 `computeRgbAbsoluteMetrics` 作为独立标量参考，不用新算法自证正确。
  所有阈值／策略均保持“差值严格大于零且达到阈值”的语义；Luma 使用有符号 RGB 差的
  BT.709 加权绝对值，不是三个绝对通道差的加权和。亮度差 `(0,1)` 只在阈值零计数。
- 请求与批次移除显示阈值／策略字段；采样结果传递分析数据。控制器改变显示参数时仅更新
  查询及通知，不取消作业、不清缓存、不提交新解码。正在执行的分析也可供新阈值查询。
- 复用只针对**当前会话输入下已有的分析**。播放头移入未采样位置、缓存淘汰或输入变化仍需
  正常采样；本批不保证所有操作都零解码，也未给图片指标新增分析缓存。
- 缓存身份包含会话／纪元、源对、对齐版本、不可变素材集合、canonical 帧数／时间线、
  源时间线、偏移、序列映射和对齐模式。不可变大映射以共享句柄标识，不在 GUI 线程逐帧
  哈希或复制。句柄更换会保守失效，即使其内容等价。
  完整帧 RGBA8 转换及公式 `cpu-rgb-absolute-v1` 在本构建内固定；以后新增 ROI、可选转换
  或公式，必须先纳入分析身份。当前不做跨会话／跨进程持久缓存。
- 缓存身份不含临时 request／playback generation，但结果提交必须匹配**完整当前分析请求**
  `PlaybackRequestContext`，并继续校验源对及对齐版本。过期批次／失败不结束或污染当前工作；
  同一失败在多个排队唤醒中只消费一次。
- 不可比较的样本保留 `comparable=false`，不能因为查询返回默认数值而当成零误差。
- 新分析每帧约 6.1 KiB。默认／硬上限 4096 个样本，分析缓存约 25 MiB（不含临时批次）；
  配置限制在 `[1,4096]`。超限淘汰距离播放头较远的端点，而不是清空整张缓存；范围及峰值
  从保留项重算。这个预算独立于解码帧缓存，并非 256 MiB 解码缓存门禁的实测证明。

## 最终性能候选

同机、MSVC Release、热文件缓存，i7-13700KF／Windows 11；复用上一批双源合成
H.264 1920×1080、60 fps、301 帧、GOP=60、B 帧=3、yuv420p 素材，B 加
`eq=brightness=0.02`。请求 `[0,300]`、priority=150。MediaProbe 在计时外。
预热一次、测量五次；中位数及 nearest-rank P95 排除预热，不挑最快轮。

| 项目 | 上一批单阈值采样 | 本批三策略分析最终候选 |
| --- | ---: | ---: |
| 首次完整窗口中位／P95（ms） | 7205.0103 / 7445.3109 | 7923.0905 / 8199.6802 |
| 首批中位／P95（ms） | 346.8001 / 358.2940 | 341.0084 / 345.3707 |
| seek | 4 | 4 |
| 实际解码帧（含前滚） | 662 | 662 |
| 单源 RGBA 返回／canonical 样本 | 602 / 301 | 602 / 301 |
| MAE 汇总 | 272.3277943351336 | 272.3277943351336 |

首次分析中位成本增加 **9.97%**：一次计算三个策略的分布，而不是只计算一个显示谓词。
这不是“首次解码更快”的证据；收益是后续查询不再重复解码或像素扫描。

- 对全部 301 个分析样本查询 `3 × 256 × 301 = 231168` 次：
  **中位 0.8662 ms，P95 1.1837 ms**；seek／解码／返回样本数保持不变。
- 每轮排序后的完整分析对象均与预热参考逐项比较，包括全部分布；查询 checksum 各轮均为
  `3818677965`。独立标量一致性由下面的 domain／application／真实控制器测试验证。
- 真实 `PairMetricsService → PairMetricsController` 组件测试使用双源 H.264／H.265
  320×180、30 fps、12 帧，预取整段后查询当前帧全部 768 个阈值／策略组合：
  提交次数仍为 1，取消为 0，seek **4 → 4**，实际解码 **30 → 30**；
  最终 Release 查询循环为 0.0263 ms。另取 18 个组合，用独立解码及旧标量实现逐项验证
  当前帧 MAE／MSE／PSNR／最大误差／坏点数／比例。

查询计时不包含 QML 布局／绘制／屏幕呈现；首批计时止于 worker sink 收到结果。
这些数值不是实际 GUI 响应、真实用户素材或五分钟 D3D11VA 播放门禁。

### 没有隐藏的初版退化

首个分析实现逐像素调用 `std::floor`，同协议完整窗口中位约 31.86 秒，未作为最终候选。
改为有界正数截断（与 floor 等价）、整数 min／max 分桶、明确展开三个通道，避免重复
浮点转换与库调用；RGB 累加及有符号亮度的运算顺序与参考一致。初版及修正后的原始日志
均保留。质量检查之后再次测量，正文只采用 `final-performance.log`，而非较快轮或预热。
