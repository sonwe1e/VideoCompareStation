# 视频视口倍率与真实尺寸

## 2026-10-08：支持小于 Fit 的 100%（修复候选，Windows 待验）

用户已将 PR #45–#49 合入本地 main 后反馈「设为 100% 没有作用」。这不是未拉取修改：
旧 `viewScale >= 1` 的下限让已被 Fit 放大的小视频无法缩小。例如 801×601 视口中，
160×90 视频在 1× DPR 的 Fit 约为 499%；真实 100% 要求 `viewScale ≈ 0.20025`。
本节替代下方历史入口说明中的「下限为适应窗口」，历史验证记录保留。

### 本次行为与范围

- 点击时把首个显示源设为**当前窗口下的 100%**。当目标小于 Fit，保留整块 ROI、
  缩小目标矩形并居中；留白不映射为视频内容，不能从留白开始缩放或框选。低于 Fit
  的平移不移动图像。达到或高于 Fit 的既有采样、缩放中心和目标矩形保持不变。
- ROI、当前帧、参考源、候选、比较模式与分割线不因 100% 动作而重置。Fit 保留 ROI，
  reset 清除 ROI。窗口改变大小后继续采用原来的相对 Fit 倍率，读数可能随之变化；
  再点 100% 重新设定。没有引入持续原始像素锁定或新的缩放模式状态机。
- 新 below-Fit 路径区分采样范围 `1 / max(scale, 1)` 与目标矩形缩小。原有
  `sourcePanelRects.contentWidth/Height` 仍是 Fit 基准，读数只乘一次 viewScale。
- 数值下限使用正的 normal-float，共享上限 64；用户可达下限还要求每个显示轴至少
  占一个物理像素。更小的 ROI 原始像素范围、不能容纳目标的窗格和不支持的场景映射
  不伪装成成功：100% 不可达时禁用动作，并保留当前读数和原因。resize/DPR/布局变化
  若使已有 below-Fit 画面变得不可显示，则抬高到安全下限，必要时退回 Fit。
- Qt 在奇数窗口、分数 DPR 下对 swapchain 大小和投影范围各取整一次。因此名义 DPR
  表示用户的 100% 意图，实际 clip/viewport 网格决定最终尺寸与采样相位；不能仅把
  对齐误差阈值放大。普通 99.8% 等缩放不会被当成 100% 强制吸附。
- 仅新 below-Fit 的原始尺寸轴做相位对齐，保留旋转后 ROI 的分数像素起点。若窗格
  容得下原始尺寸但没有可用的整相位位置，保留完整 ROI 和正确尺寸；此紧贴边界的
  情况仍可能插值。旧的 >= Fit 路径也不在本轮宣称无重采样。
- 非方形 SAR 继续保留显示比例、分别报告横纵倍率；某一轴达到 100% 不等于两轴 1:1。
  纯 Difference/Fade 原本不显示该徽标，本轮没有另加入口；切入这些模式仍使用同一
  below-Fit 几何。图片工作区与模式枚举不变。

支持范围是实际 Main 的普通、未缩放、轴对齐窗口布局。任意祖先缩放、旋转、透视和
自定义 redirected render target 不在本轮 UI 倍率保证内；无效的网格或数值按不可显示
处理，不使用 Qt 私有接口或广泛的场景祖先监听器。对应 Qt 规则依据为
[QQuickWindow 投影构造](https://github.com/qt/qtdeclarative/blob/v6.11.1/src/quick/items/qquickwindow.cpp)、
[QSize 取整除法](https://github.com/qt/qtbase/blob/v6.8.2/src/corelib/tools/qsize.h) 和
[D3D11 swapchain 大小](https://github.com/qt/qtbase/blob/v6.11.1/src/gui/rhi/qrhid3d11.cpp)。

## 复现与行为

原徽标按「第一个面板宽度 ÷ 槽位 0 视频宽度」计算倍率，有三个问题：

- 竖屏在宽面板中的左右留白被算进了视频宽度。
- 参考聚焦、B/C 分割线的首个显示源可能不是槽位 0。
- 分割线面板是裁切遮罩，移动分割线会改变它的宽度，却不应改变画面倍率。

一个 800 × 600 的独立视口（边缘各 1 像素）显示 1080 × 1920 的竖屏视频时，
实际内容为 336.375 × 598；适应窗口倍率约 31.15%，旧徽标却报约 73.89%。
旧按钮根据这个错误倍率放大后会显示“100% 真实尺寸”，实际内容比例仍只有约 42.15%。
新按钮以实际内容尺寸计算，目标 `viewScale = 1920 / 598`，再点一次恢复适应窗口。

## 实现范围

- `ComparisonSurface::sourcePanelRects()` 复用既有
  `computeSurfacePresentationGeometry()`，保持原 panel x/y/width/height/slot，并增加
  `contentWidth` / `contentHeight`。分割线返回完整合成画面的内容范围。
- 设置、清除、恢复 ROI 时发出已有 `presentationGeometryChanged` 信号，保证裁切改变
  内容宽高后，徽标不会保留旧几何。
- 徽标跟随首个显示源，计算裁切后的原像素宽高、90°/270° 旋转和逻辑到物理像素的 DPR。
- 方形像素仍显示单一百分比；非方形像素分别显示横/纵百分比，不宣称两轴同时为 1:1。
- “100% 真实尺寸”的两轴容差由 2.5 个百分点收紧至 0.001 个百分点。
  现有 64× 上限仍由 surface 保持；达不到 1:1 时显示真实倍率。
- 不改播放、解码、D3D11 绘制、同步、分割线位置、缩放/平移算法或比较对象选择。
  纯差异/Fade 模式原本不显示这个源面板徽标，本轮不扩展入口。
